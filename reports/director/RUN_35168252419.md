## Must-Fix Findings (5)

### MF-1: No Compenser action
The V3-04 objective requires compensation "produit un CrossLedgerSettlement immuable avec avant/après". Constitution §8 requires a `Compenser` action where the user chooses contribution credit, sees the money amount per the group-defined rate, validates with Avant/Après preview, and persists an immutable `CrossLedgerSettlement`. The candidate only renders a status card. `quoteCrossLedgerMoneyAmount` is imported but never called (dead import). No UI calls `repos.settlements.create` despite the repository and preconditions existing.

**Repair**: Implement Compenser action (inline or modal) on Balances screen: select creditor + amount, quote money amount, display Avant/Après preview, validate preconditions, persist `CrossLedgerSettlement` with rateSnapshot, refresh both ledger views. Disabled when `crossLedgerCompensationEnabled=false` or no rate. Tests: settlement creation persists `CrossLedgerSettlement` with correct `moneyAmountMinor` matching snapshotted rate; before/after preview equals post-settlement balances; both ledgers zero-sum.

### MF-2: Missing filtered history section
Objective requires "suggestions pair-à-pair et historique". Constitution §9 requires filtered history at the bottom of the screen. Constitution §10 requires filters Tout/Contributions/Dépenses/Compensations. `activityLog.ts` already supports merged contribution/expense/settlement streams with a `settlement` filter, but Balances has no history section.

**Repair**: Add filtered history section at bottom of Balances (Tout / Contributions / Dépenses / Compensations), reusing `paginateActivityLog` with settlements included, compact rows per §10, paginated and cached per V3_BACKEND_FRUGAL §6. Tests: merged history includes settlements and respects each filter.

### MF-3: Delta materialized views not wired, screen shows stale balances
Objective requires balances "mises à jour par delta plutôt que par replay intégral à chaque affichage". Screen does full replay on mount and never refreshes (expo-router tabs stay mounted with `unmountOnBlur` default false), so entries added in Ajouter tab never appear in Balances. `materializedBalances.ts` is imported only by tests, never by app code.

**Repair**: Wire delta materialized views into the screen: maintain materialized snapshot, apply deltas on entry add/remove/settlement, refresh on focus or data-change signal from AppContext so Balances reflects new entries without full replay. Cost-gate test exercises actual screen refresh with repository call counts, not wall-clock time.

### MF-4: Settlements not period-filtered
Period views filter contributions and expenses by `occurredAt` but pass the full settlements array unfiltered into balance calculations. A settlement from any date affects Semaine/Mois/Année views, contradicting "une période n'est qu'une vue sur les écritures du ledger" (constitution §6, §8).

**Repair**: Filter settlements by period (`filterByPeriod` on `occurredAt`) before computing period balances, in both screen and materialized service. Tests: settlement dated 2020 does not appear in week/month/year views but appears in all-time; both ledgers remain zero-sum for every period.

### MF-5: Weak/misleading cost-gate test
Test "navigating Add → Balances → Todos → Add does not re-fetch balances 4 times" exercises neither navigation nor the screen: it calls `getByHousehold` 4 times in parallel. Wall-clock timing assertions (`<200ms`, `<100ms`, `<50ms`, `<5ms`, `<500ms`) are flaky and do not measure remote reads or repository call counts.

**Repair**: Replace with a test that exercises the real refresh contract: render the Balances screen against a fake repo, add an entry, assert the view updates via delta without a full re-read. Bounded-read assertion based on repository call counts rather than wall-clock time. The test should fail against the current mount-only implementation and pass once the delta/refresh wiring from MF-3 exists.
