## Must-fix findings (current cycle)

### 1. Missing import of ScopedContributionRepository / ScopedExpenseRepository

**Path:** `__tests__/domain/v3-06-repair-sync-authorization.test.ts` (import block lines 20–23; usages at 637, 652, 672, 687, 707, 724, 745)

The import was trimmed to only `createScopedRepositories` but the "authorization enforced through repository path" describe block still instantiates `new ScopedContributionRepository(...)` and `new ScopedExpenseRepository(...)`. Both classes are still exported from `ScopedRepositoryFacade.ts`. This produces 7 TS2304 errors and 7 runtime `ReferenceError` test failures.

**Required fix:** Restore the import of `ScopedContributionRepository` and `ScopedExpenseRepository` from `../../src/infrastructure/repositories/ScopedRepositoryFacade` (or rewrite the 7 tests to use `createScopedRepositories`). Then verify `tsc --noEmit` exits 0 and the "authorization enforced through repository path" describe block passes.

### 2. Failure-injection test spread loses prototype methods

**Path:** `__tests__/domain/v3-06-repair-sync-authorization.test.ts` lines 972–978, assertion at 1013

The injected failing repo is built as `{...originalContributions, seed: throw, create: throw}`. Spreading a class instance copies only own enumerable fields (`inner`, `syncState`); all prototype methods (`getById`, etc.) are lost. The production `MaterializingSyncState.applyDeltas` → `materializeDeltas` → `upsertWithConflictResolution` calls `repos.contributions.getById(record.id)` **before** `seed` (SyncMaterializer.ts line 213), so the actual error is `repos.contributions.getById is not a function` instead of the intended `Simulated materialization failure`. The test fails and does not prove the intended scenario.

**Required fix:** Inject via `Object.create(originalContributions)` with overridden `seed`/`create` (or a Proxy) so the prototype chain is preserved. Then assign `(repos as any).contributions = failing` before `pullDeltas` and restore afterwards. Keep the assertions that cursor did not advance and all 7 business tables are unchanged after rollback. Verify the test passes with the intended `Simulated materialization failure` error.

### 3. SQLite factory-wiring test uses raw sync state

**Path:** `__tests__/infrastructure/repositories.test.ts` lines 1013–1105 (pull at 1064, assertion at 1075)

The test passes the raw `SqliteSyncStateRepository` to `pullDeltas` instead of a `MaterializingSyncState` wrapping it (as the factory does in RepositoryFactory.ts lines 441–442). Raw SQLite `applyDeltas` is buffer-only — it writes to `sync_records` but never materializes into business tables. The remote delta never becomes a readable business record and the `entry not null` assertion fails.

**Required fix:** Wrap `baseSyncState` in a `MaterializingSyncState` (export the class from RepositoryFactory or replicate the factory wiring in the test) and pass that wrapped state to `pullDeltas`. Keep the assertions: remote delta → business record readable; local write via wrapped repo → `getDirtyRecords` returns the payload; `pushDeltas` sends it. Verify the test passes with `entry.label === 'Remote via factory'` and `entry.value === 30`.
