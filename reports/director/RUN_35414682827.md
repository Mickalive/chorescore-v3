### Why this is repair, not accept

The audit independently queried GitHub API and found:

- **Run 35413347057** (head_sha `0f36b1f`, "Fix V3 finalizer emulator shell"): the workflow at that commit **already contained** `script: bash scripts/finalizer-e2e.sh` (single-line form). The multi-line block was fixed **before** this run started.
- Job step 7 "Android API 35 install, launch and golden path" **failed** — exit code 1, annotation "The process '/usr/bin/sh' failed with exit code 1", duration ~10 minutes.
- Steps 5 (gates) and 6 (APK locate/hash) **succeeded**.

**Historical pattern:**

| Run | Form | Outcome |
|---|---|---|
| 35293489693 (11) | multi-line | FAILED (exit 2 — dash rejects pipefail) |
| 35302658175 (12) | multi-line | FAILED (exit 2) |
| 35315519533 (14) | multi-line | FAILED (exit 2) |
| 35333103534 (16) | multi-line | FAILED (exit 2) |
| **35413347057 (22)** | **single-line** | **FAILED (exit 1, ~10 min)** |
| Schedule runs (9,10,13,15,17-21) | — | Release job SKIPPED (never ran emulator) |

The multi-line form caused exit-2 failures in runs 11/12/14/16 (dash rejects `set -euo pipefail`). But run 22 used the single-line form and failed with exit 1 — a **different root cause** that is currently unknown.

The candidate's regression-guard comment says: "Regression guard for Actions run 35413347057: the multi-line `script: |` form … exits 2 before the APK install and golden path ever run." This is factually wrong for run 35413347057 (it had the single-line form, exited 1 not 2, and ran for ~10 minutes). The guard itself is valid (it prevents future regressions to the multi-line form), but it does not fix the mustFix.
