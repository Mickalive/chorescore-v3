## Must-fix findings (repair scope)

### F1 — Trusted verification exit 2 (test-file type errors)
8 TypeScript errors in `__tests__/domain/v3-07-analytics-privacy.test.ts`:
- Line 434: `label` not in anonymous event union type
- Lines 501–505: partial records missing required union fields
- Line 730: `'commercial-use'` not a valid `DataProcessingPurpose`
- Line 870: invalid cast to `Record<string, unknown>`

**Fix:** Use `as unknown as`/`as any` for intentionally malformed test records; use full valid event shapes for clean-product records; replace `'commercial-use'` with a valid purpose or cast.

### F2 — Pipeline label contradiction (core broken path)
`validateNoOperationalIds` (pipeline.ts) lists `label` as forbidden input, but `transformContributionCreated` and `transformEntryCreated` require `label` for classification. Every contribution/entry fact is rejected at stage 1 — transforms are dead code. This breaks the core V3-07 acceptance: "événements V3 couvrent contributions dépenses settlements usage."

**Fix:** Remove `label`/`title`/`notes` from the input-forbidden list (these are consumed for classification, never emitted). Rely on output event types + PrivacyReleaseGate to guarantee no free text in outputs. Add a test proving labeled contribution transforms successfully with no text in the emitted event.

### F3 — Gate tests unpassable (test data too small)
`assessReIdentificationRisk` flags datasets < 10 records with `re_identification_risk` (high severity), which blocks approval. The "approves clean product" test uses 5 records and the "audit log" test uses empty data — both expect `approved=true` but the gate returns `approved=false`.

**Fix:** Use ≥10 records with repeated (category, month, beneficiaryCount) combinations so `combinations.size ≤ facts.length * 0.8` and `facts.length ≥ minCohortSize * 2`. Do not weaken the gate's anti-reconstruction protections.

### F4 — Query budget test/implementation mismatch
Test expects `remainingQueriesThisMinute=1` after first query with `rateLimitPerMinute=3`. Service returns `limit - queriesThisMinute - 1 = 2`.

**Fix:** Align test and implementation on one documented semantic (either "remaining after this query" = 2, or "remaining including this query" = limit - used). Update the test or the service accordingly.

### F5 — Consent expiry same-millisecond race
`retentionDays: 0` with strict `<` comparison: when `recordConsent` and `getExpiredRecords` run in the same millisecond (jest), the record is not expired. Standalone execution with a 1ms gap passes.

**Fix:** Use a negative retentionDays (e.g. `-1`) so cutoff is strictly in the future of any just-created record, or change comparison to `<=`. Keep semantics documented and deterministic.
