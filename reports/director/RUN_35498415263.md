## 3. The mustFix finding

**Crash-detection in `waitFor()` is unreachable code.**

- `adb shell pidof <package>` exits 1 with empty stdout when the app process is dead (Android toybox semantics).
- `execFileSync` throws on non-zero exit; the `adb()` wrapper retries 3× then rethrows.
- The `waitFor()` catch swallows the error (`'pidof failed — proceed with normal wait'`).
- The `if (!pid)` relaunch branch is therefore **unreachable** in the exact crash scenario the feature targets.
- The loop still burns the full timeout with empty dumps — the failure mode it was written to fix.
- The guarding test asserts only static substrings (`APP CRASHED`, `pidof`, `force-stop`, `monkey`) and passes regardless of behavior.

**Required fix:** Distinguish pidof's "no process" exit (`err.status === 1`) from adb transport failures. Treat `err.status === 1` as app-dead → invalidate dump cache, force-stop, monkey relaunch, sleep 15s, continue. Treat other errors (transport) as "proceed with normal wait". Strengthen the wrapper test to verify error-status handling.

## 4. Informational findings (all `mustFix=false`)

1. **Screenshot cache-reuse test is static-string-only.** Feature is functionally correct (verified by reading). No action required this cycle.
2. **Adb-restart-removal test does not assert absence of `adb kill-server`.** Current wrapper is correct (no kill-server command remains). Consider adding `not.toMatch(/adb kill-server/)` in a future cycle.
3. **Pidof check overhead on degraded transport** (up to ~10s per 30s check with retries=3). Bounded by the waitFor deadline. Reduce retries if step logs show excessive overhead.
