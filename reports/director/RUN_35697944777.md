## Summary

V3-08 repair accepted. The candidate fixes the trusted finalizer Android API 35 APK install/E2E blocker from Actions run 35692317866: install timeouts raised from 120s/180s to 300s, plus a conditional adb server restart and an `adb push` + `pm install` fallback via shell transport.

### Root cause

A 43 MB release APK install on API 35 x86_64 takes 3-4+ minutes (observed **208s** in run 35650859523), while the previous bounds were **120s** in the wrapper and **180s** in the e2e script. Runs 35670332996, 35678248910, 35684869621 and 35692317866 all failed with 2×120s empty-output timeouts while the `pm` path later proved the package **was** present — the device-side install completed but the adb client was killed first (and a degraded adb sync service could hang the connection).

### Fix

1. **Timeouts → 300s** in both `scripts/finalizer-e2e.sh` and `scripts/e2e-android.js` (92s headroom over the observed 208s).
2. **Skip install when already present:** both scripts check `adb shell pm list packages app.chorescore.v3` and skip — safe because the finalizer emulator boots fresh with snapshots disabled, so the package can only come from this run.
3. **Conditional adb server restart** (`kill-server`/`start-server`/`wait-for-device`) before the **first install attempt only**, recovering a degraded sync service without destabilising the golden path.
4. **Fallback:** `adb push` to `/data/local/tmp` + `adb shell pm install -r` via shell transport (more resilient than the sync service), bounded push 180s / pm 300s in both wrapper and e2e.
