## 2. What was repaired

The previous cycle added a uiautomator warm-up dump and widened the Demarrer window to 360s, but the finalizer STILL failed. The root cause was not the warm-up mechanism itself but the **proactive adb server restart (kill-server + start-server) in `launch()` executed under heavy Hermes cold-start load**, immediately before the uiautomator warm-up dump. This restart disrupts the adb transport exactly when the uiautomator server needs to initialize, causing the warm-up dump to fail and the first real `dumpUi()` to block for the full 45s timeout, burning the Demarrer `waitFor()` window.

Repair (three coherent facets):

- **(a) Removed proactive `adbReconnect()` from `launch()`** — the kill-server/start-server restart that ran after the cold-start sleep and before the warm-up dump is eliminated. All reactive recovery paths are preserved: `adb()` timeout retry, `dumpUi()` cat-failure, `waitFor()` consecutive-dump-failure.
- **(b) Removed post-install adb server restart in `finalizer-e2e.sh`** — the kill-server/start-server + waits (~13s) after package install is removed. The pre-E2E idle restart (before install, when the transport is quiescent) is retained.
- **(c) Reduced non-deadline sleeps** — cold-start sleep 60s→30s, package-manager settle 60s→30s. The Demarrer window is unchanged at 360s. The worst-case time before the window actually decreases because the disruptive restart is gone.
