## What the accepted delta delivers

**Failure diagnosis (finalizer run 38053121004):**

- **Failure class:** harness false-negative — `uiautomator` prunes off-screen nodes, and the dump cache survived
  `swipeToTop()`, so lookups read the **stale pre-reset** dump and missed controls located further down the form.

**Concrete fix (minimal, targeted, in `scripts/e2e-android.js`):**

1. **Cache invalidation on scroll reset.** `_dumpCache = null` is set at the start of `swipeToTop()` so no stale
   pre-reset dump can survive a scroll reset.
2. **Bounded deep sweep in `findByTestId()`.** After the fast path, the helper resets to the top and walks the
   whole scrollable form with **fresh** dumps, bounded by a **60s budget** so a genuinely missing node cannot blow
   past `openCreateGroupForm()`'s 240s recovery loop on a slow emulator.
3. **Two unnecessary `swipeToTop()` calls removed** before `add.categoryName` and `add.memberName`: both inputs sit
   directly above the action just revealed, and resetting pushed them several screens below the fold.

The golden-path assertions are **not weakened**: `openCreateGroupForm()` must still make `groups.nameInput` appear
or the run fails; real app ANRs still force-stop + relaunch; `findByTestId(!scroll)` still throws when the node is
absent.
