## 2. What this cycle addressed

The previous trusted finalizer run (`35490543018`) failed at step 7 (Android API 35 install/launch/golden path). The root cause identified by the Auditor: on degraded API 35 x86_64 emulators the SQLite native open hung indefinitely, leaving `createRepositories()` never-resolved and the app stuck on the `"Chargement..."` loading screen for >10 minutes, so `waitFor('Demarrer', 600000)` timed out even though the APK installed and the process stayed alive.

The accepted repair:

1. **`src/infrastructure/repositories/RepositoryFactory.ts`** — bounded SQLite initialization: `SQLITE_INIT_TIMEOUT_MS=45_000` with a new exported `withTimeout(promise, ms, fallback)`; `createRepositories()` races the SQLite attempt against the timer and falls back to the existing in-memory repository set (the same fallback already used on `catch→null`). Healthy devices open SQLite in <1s so the timer never fires; degraded emulators reach the sign-in/Démarrer screen instead of hanging.
2. **`scripts/e2e-android.js`** — `waitFor` timeout now echoes the current UI dump text/content-desc nodes (up to 40) to stdout, because dump XMLs under `audit/android-e2e/*.xml` are not uploaded when the emulator step fails. This is the only way screen content at timeout survives in step logs.
3. **`scripts/finalizer-e2e.sh`** — failure branch now `cat audit/android-e2e/*.xml` under header `UI dump XML files` so checkpoint XMLs survive as step output.
4. **`__tests__/infrastructure/repositories.test.ts`** — 4 new tests for `withTimeout` (promise wins, timer wins, rejection, late settlement without unhandled rejection).
5. **`__tests__/domain/v3-08-finalizer-wrapper.test.ts`** — 2 new static contract tests guarding the diagnostic echoes.
