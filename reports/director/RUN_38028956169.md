## What the accepted delta delivers

Delta is exactly two files — `scripts/e2e-android.js` (144 changed lines) and
`__tests__/domain/v3-08-finalizer-wrapper.test.ts` (41 changed lines). **No product, ledger, sync, analytics,
privacy, theme, chrono or premium file was touched.**

Per `V4_RELEASE_ENGINEERING.md` §7 (« une répétition identique sans nouvelle preuve doit changer de stratégie, pas
seulement augmenter les timeouts »), the pure-retry strategy is replaced by **three distinct mechanisms**:

1. **`longPressNode()` — held touch.** `input swipe` at fixed coordinates for 150 ms instead of a 0 ms
   `input tap` whose DOWN and UP carry the same timestamp, so the DOWN is delivered before the UP under load.
   React Native still fires `onPress` on release, so this is a drop-in replacement on the `TouchableOpacity`.
2. **`relaunchApp()` — bounded recovery.** After every 3 dropped attempts the app is force-stopped and relaunched to
   replace a stale window/input channel with a fresh one; the deterministic E2E session restores Groups on launch,
   and the cold-start grace is reset so the relaunched app is not killed by the stuck-app detector. The same helper
   now also serves the app-ANR path in `dismissAnrOverlay()` (SystemUI infra ANR still only taps Wait — no
   force-stop).
3. **`stabilizeEmulator()` — remove the load source up front.** Before launching: disable the crash-looping
   Bluetooth service (`cmd bluetooth_manager disable`, `svc bluetooth disable`, `settings global bluetooth_on 0`),
   zero the three animation scales, keep the display interactive (`svc power stayon true`). Each command is bounded
   to 10 s with a single attempt so a stuck service cannot stall the run.

**No assertion is weakened:** `openCreateGroupForm()` still must make `groups.nameInput` appear within 240 s or the
golden path fails; real app ANRs still force-stop + relaunch; the regression test asserts the old identical-retry
pattern (`tapTestId('groups.createButton'`) is **gone**, the three strategy changes are present, `stabilizeEmulator()`
runs before `launch()`, and the form-open step still precedes `typeIntoTestId('groups.nameInput', ...)`.
