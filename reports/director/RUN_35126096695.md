## Must-fix findings (4)

### 1. Money precondition sign inversion — `settlementPreconditions.ts`

`checkMoneyDebtSufficient` computes `availableDebt = -counterpartyMoneyBalance` and requires it ≥ settlement amount. This requires the counterparty to **owe** money. But per the accepted baseline test (`ledgers.test.ts` — b paid 3000, a owes b → b has +1500), the counterparty is the member **owed** money (positive balance). Valid settlements are rejected; semantically invalid ones are accepted.

**Fix**: `sufficient = counterpartyMoneyBalance >= moneyAmountMinor - 1e-9`. Expose `availableReceivable = counterpartyMoneyBalance`. Fix error message.

### 2. Sequence accumulation dead code — `validateSettlementSequence`

`appliedSettlements` is pushed but never read. Every iteration recomputes balances from raw entries with empty settlements. A sequence consuming 30 min against 15 available passes.

**Fix**: Thread applied settlements into balance computation. Either add overloads to `calculateContributionBalances`/`calculateFinancialBalances` accepting a prior-settlements parameter, or compute adjusted balances: `baseBalance - sum(consumed amounts from prior matching settlements)`.

### 3. Replay accepts rate-inconsistent settlements — `contributionLedger.ts` / `expenseLedger.ts`

`validateSettlement` and `validateSettlementMoney` check structure only (members, positive amounts, unit/currency match) but never verify `moneyAmountMinor` matches the snapshotted rate quote. `validateCrossLedgerSettlement` does this correctly.

**Fix**: Replace the inline validators in both replay paths with `validateCrossLedgerSettlement` from `crossLedgerSettlement.ts`.

### 4. Tests encode inverted semantics — `validation-preconditions-periods.test.ts`

The "valid settlement" test uses a counterparty with negative balance (contradicting accepted baseline). The "sequence catches over-settlement" test passes because s1 fails the inverted money check immediately — it never exercises accumulation. No test covers replay rejection of rate-inconsistent settlements.

**Fix**: Rewrite to accepted baseline scenario (counterparty +1500, settlement valid). Add genuine accumulation test (s1 consumes all, s2 overshoots → invalid). Add replay rejection test for rate-inconsistent settlements.
