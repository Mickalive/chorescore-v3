### Diagnostic additions

1. **Periodic mid-wait diagnostics inside `waitFor()`** (every `DIAGNOSTIC_INTERVAL_MS = 120_000`):
   - App process state (`pidof`)
   - Filtered logcat (Hermes, SQLite, ReactNative, expo, FATAL, ANR, crash, Exception, Error)
   - Top activity via `dumpsys activity activities`
   - Dump-cache state (failures, cache age, consecutive empty count)

2. **Cold-start diagnostic snapshot 30s after `launch()`**: pidof + dumpsys + init logcat during the critical Hermes/SQLite window.

3. **WARMUP visible-elements logging**: first 15 text/content-desc nodes from the warm-up uiautomator dump echoed to step logs.

All diagnostics are read-only adb calls, wrapped in try/catch, bounded (8–10s timeouts, 120s cadence), and echoed to stdout so the evidence survives in GitHub Actions step logs even when the artifact directory is not uploaded.

## Why this is the right move

The previous cycle (35660497212) identified that the Demarrer `waitFor('Demarrer', 900000)` times out because the app never shows the "Demarrer" sign-in button within 900s, and that the wrapper has no hard step timeout — so reducing wrapper overhead cannot change the E2E outcome. However, the exact failure point was unknown (artifact HTTP 401, step logs HTTP 403). Any product fix without diagnostic evidence would be a blind guess.

The diagnostics are the prerequisite: they ensure the next finalizer run captures the process state, logcat, and screen state every 120s during the Demarrer wait, plus the earliest state after launch. If the blocker persists, these snapshots will pinpoint whether the app crashed, hung on Hermes init, was stuck on splash, hit a System UI overlay, or had a dump fragility issue.

## Two non-must-fix observations (not blockers)

1. **Cold-start snapshot skipped if pidof throws at 30s** — if the app is dead at 30s, the snapshot is skipped. The `waitFor` app-alive check and timeout diagnostics still capture crash evidence. Optional hardening: split pidof from dumpsys/logcat.

2. **Mid-wait logcat uses default retries** — could trigger `adbReconnect` (~10s) inside the wait loop. Consistent with existing patterns and bounded (10s timeout, 120s cadence). Optional refinement: `{ retries: 1, allowReconnect: false }`.
