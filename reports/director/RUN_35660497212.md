## Why the emulator still fails

The step has **no hard timeout** (no `timeout-minutes` in the workflow; the action runs the script via `exec.exec('sh', ['-c', script])` with no timeout wrapper). The E2E script's `waitFor` deadlines are fixed:

- `waitFor('Demarrer', 900000)` — **900s fixed window**
- `waitFor('Appartement', 300000)` — 300s
- `waitFor('Ajouter', 300000)` — 300s

Step 7 of run 35650859523 failed at **20m59s = 1259s**. Timing reconstruction:
- Wrapper overhead: ~210–235s (boot check ~5s + settle 10s + health ~5s + install ~150–180s + post-install ~1s)
- `launch()`: ~120–150s (30s sleep + dumpsys polls + uiautomator warm-up)
- `waitFor('Demarrer')`: **900s timeout** — the app never showed the button

Total: ~1230–1285s ≈ 1259s. The step duration matches the Demarrer `waitFor` timing out.

The wrapper timing improvements (boot 420s→60s, settle 30s→10s) save ~50–90s of wrapper overhead. But since the step has no hard timeout, this only shifts the failure earlier — it does not change whether the app shows "Demarrer". **The blocker is in the app cold start / demo sign-in / initial render phase**, or possibly dump fragility / System UI overlay during that phase.
