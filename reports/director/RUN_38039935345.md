## What the accepted delta delivers

**Failure diagnosis (finalizer run 38034294332):**

- **Last product step reached:** x86_64 release build — succeeded `07:34:10`.
- **Failure class:** `infra_android_adb_emulator` — post-boot `settings put` / `input keyevent 82` →
  `"Broken pipe (32)"`, step exited `224` at `07:43:09`; emulator boot took `498359 ms`.

**Concrete strategy changes (not a timeout-only retry):**

1. **Emulator ownership / boot gate (`boot-emulator.sh`).** The repository owns the emulator lifecycle. A live
   framework-service readiness gate requires ADB `state=device` **and** `service check package/activity/input/settings`
   all `found` **and** a real `settings get system screen_off_timeout` round-trip **and** a real `input keyevent 0`
   round-trip. `sys.boot_completed=1` alone is explicitly rejected as insufficient.
2. **Active ADB transport recovery.** On the broken-pipe signature the script runs `adb reconnect offline →
   wait-for-device`, and if still dead `kill-server → start-server → wait-for-device`, with bounded retries in both
   `boot-emulator.sh` and `finalizer-e2e.sh`.
3. **Extended boot timeout.** `EMULATOR_BOOT_TIMEOUT` raised **600 → 900 s** to match the observed 498 s boot.
4. **Bounded ANR handling (`e2e-android.js`).** `dismissAnrOverlay()` distinguishes **app ANR** (dialog names
   ChoreScore / `app.chorescore.v3` → tap Wait → force-stop + relaunch) from **infra ANR** (Quickstep/SystemUI/
   system/phone → tap Wait → re-assert foreground **without** force-stop), ending the infinite kill loop.
5. **Metro cache clearing + E2E bundle-output eviction.** E2E rebuild deletes bundle outputs before
   `gradlew assembleRelease`, and clears the same outputs post-E2E so the **arm64** release rebuild cannot leak the
   E2E session.
6. **Keyguard dismissal / error-dialog suppression.** Bounded `input keyevent 82` + `wm dismiss-keyguard` with
   verification, plus `hide_error_dialogs=1`, so SystemUI/launcher ANR dialogs never steal focus.

The golden-path assertion is **not weakened**: `openCreateGroupForm()` must still make `groups.nameInput` appear or
the run fails, and real app ANRs still force-stop + relaunch.
