## Remaining must-fix findings

### 1. Currency-only expense edit corrupts all-time money snapshot
The expense modification detection in `balances.tsx` (lines 321-355) checks `amountMinor`, `paidByMemberId`, `participantMemberIds`, `splitMode`, and `customShares` — but **not** `currency`. The Add-tab edit form exposes an editable currency field and persists it (add.tsx line 532). A user can change an expense from CHF to EUR without changing any detected field. The handler classifies it as unmodified, keeps the old CHF effect, and never applies the new EUR effect. The all-time `moneyByCurrency` snapshot diverges from full replay.

**Fix:** Add `currency` (and verify no other ledger-affecting field is missing) to the modification condition. Add a test performing a currency-only edit and asserting the all-time moneyByCurrency snapshot equals `calculateFinancialBalancesByCurrency` full replay (old currency zeroed, new currency carries the amount).

### 2. Required screen-level test still absent
The header claims "**Screen-level**: delta handler re-reads only the changed collection" but the tests build a local `Set` pub/sub stand-in and never import `app/(tabs)/balances.tsx` or `AppContext`. The test would pass if the screen reverted to a full re-read.

**Fix:** Either (a) add a real screen-level test that imports the screen with `jest.mock('expo-router')`, provides fake repos with counted reads, drives add/edit/delete through the data-change signal, and asserts rendered delta + bounded reads; or (b) remove "Screen-level" from claim #8 and reword it to an explicitly data-level claim the tests actually prove. Also strengthen the settlement exactly-once test to guard the fix.
