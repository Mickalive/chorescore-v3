## What was repaired

The `waitFor()` crash-detection feature in `scripts/e2e-android.js` was non-functional: `adb shell pidof` exits 1 (throws via `execFileSync`) when the app process is dead, and the old `catch (_)` swallowed that signal, making the relaunch branch unreachable dead code. The guarding test was a weak static-string check that passed regardless of behavior.

**Repair:** The catch block now captures `err` and checks `err.status === 1` (Android toybox pidof's "no process" exit) to trigger the relaunch branch (invalidate dump cache, force-stop, monkey, sleep 15s, continue). Other errors (transport ETIMEDOUT, adb disconnect) fall through to the normal wait. The test now asserts the error-status handling itself (`catch (err)`, `err.status === 1`) so the feature cannot silently regress to dead code.
