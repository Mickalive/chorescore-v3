## Root cause hypothesis

The stuck-app detector in `scripts/e2e-android.js` uses `STUCK_APP_THRESHOLD=4` consecutive real `uiautomator dump`s with no matching label to trigger a force-stop + relaunch. On a slow API 35 x86_64 emulator (cold start documented up to 240s, dump latency 30-60s each), 4 real dumps take 2-4 minutes. A healthy app cold-starting for 240s would be force-stopped before "Demarrer (demo)" renders, and the cold start resets each cycle — creating an infinite loop of kills.
