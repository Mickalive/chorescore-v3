## The Evidence Loss Problem

The diagnostic instrumentation from cycles 35419214459/35425284987 writes logcat, dumpsys, screenshots, and result.json to `audit/android-e2e/` in the runner workspace. However:

1. **Step 8** (upload-artifact) uploads only the APK and is **skipped on failure**
2. **Raw step logs** require admin rights (403) — the Builder and Auditor cannot read them via API
3. The diagnostic files exist in the runner workspace at failure time but are **never persisted**
4. The exact failure cause of all 7 runs is **lost**

This is the root cause of the recurring no-repair cycles: without diagnostic evidence, the Builder cannot identify what to fix, and the same emulator step keeps failing silently.

## What the Builder Must Fix

The next Builder cycle must ensure diagnostic evidence survives the workflow failure. Within Builder scope (scripts only, not workflow YAML):

### 1. Echo diagnostic content to stdout/stderr in `scripts/finalizer-e2e.sh`

The script already writes logcat to `audit/android-e2e/logcat-finalizer.txt` and the E2E script writes logcat/dumpsys/result.json/screenshots to `audit/android-e2e/`. But none of this content is echoed to stdout. The fix: after the E2E fails (non-zero exit), **cat the diagnostic files to stdout/stderr** before `exit "$E2E_EXIT"`. GitHub Actions preserves step output in workflow logs even when steps fail, so this content will be visible in the GitHub UI and accessible to anyone with repo access.

Concrete additions to `finalizer-e2e.sh`:
- After line 108 (`echo "E2E FAILED..."`), add: `cat audit/android-e2e/result.json 2>/dev/null || true`
- Add: `tail -100 audit/android-e2e/logcat-finalizer.txt 2>/dev/null || true` (or the full file if small enough)
- Add: `ls -la audit/android-e2e/ 2>/dev/null || true` to confirm what files were captured
- Echo the E2E script's console.error output (already goes to stderr)

### 2. Consider additional resilience in `scripts/e2e-android.js`

The E2E script already captures logcat, dumpsys, screenshots, and result.json on failure (lines 418-434). Verify these are written to `audit/android-e2e/` and consider:
- Ensuring `result.json` contains enough structured data to diagnose (it already does: status, packageName, checkpoints, error)
- Adding a `console.error(JSON.stringify(result, null, 2))` after `writeResult('fail', error)` to echo the result to stderr

### 3. Do NOT modify protected control-plane files

- Workflow YAML (`.github/workflows/chorescore-v3-finalize.yml`) — protected
- `docs/RELEASE_STATUS.json` — protected
- `directives/TASKS.json` — protected
