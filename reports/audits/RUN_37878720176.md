## Findings (Must-Fix)

### 1. Categories and Invitations Missing from Sync Collections
**Path:** `src/domain/entities/index.ts`, `src/domain/services/syncEngine.ts`  
**Problem:** `SyncCollection` type and `SYNC_COLLECTIONS` array define only 8 collections. Categories and invitations are absent, so they **never participate in delta-only sync**. This violates V4-07 "delta-only préservé" and "sync aux catégories, membres nommés, invitations".  
**Evidence:** `SYNC_COLLECTIONS = ['contribution_entries', 'expense_entries', 'settlements', 'todo_items', 'persistent_tasks', 'members', 'memberships', 'households']`. The sync engine iterates this array for pull/push.  
**Required Fix:** Add `'categories'` and `'invitations'` to `SyncCollection` type and `SYNC_COLLECTIONS`. Implement materialization in `SyncStateRepository.applyDeltas` for both. Add sync E2E tests.  
**Verification:** Sync tests pass for categories/invitations; pull/push materializes records; cost budget updated.

### 2. Missing Cost Budgets for Category and Todo-Expense Operations
**Path:** `src/domain/services/costInstrumentation.ts`  
**Problem:** `COST_BUDGETS` lacks budgets for category CRUD and todo-expense operations. V4-07 requires "cost gate étendu".  
**Evidence:** Only 7 budgets defined: `open-household`, `tab-switch`, `create-contribution`, `complete-todo`, `sync-delta`, `create-invitation`, `accept-invitation`.  
**Required Fix:** Add budgets: `create-category` (writes: 1), `update-category` (writes: 1), `delete-category` (writes: 1), `create-todo-expense` (writes: 1), `complete-todo-expense` (writes: 2). Update `sync-delta` from 8→10 collections.  
**Verification:** Cost gate tests pass with new budgets; `costTracker.assertBudget` enforces them.

### 3. Missing Pagination for Categories, Members, Invitations, PersistentTasks, Todos
**Path:** `src/infrastructure/repositories/index.ts`, `src/infrastructure/repositories/InMemoryRepositories.ts`, `src/infrastructure/repositories/SqliteRepositories.ts`  
**Problem:** Only `ContributionEntry`, `ExpenseEntry`, `Settlement` repositories have `getByHouseholdPaginated`. The other five collections lack pagination, risking full scans on large datasets. Violates V4-07 "aucun N+1/full scan" and "historique paginé".  
**Evidence:** Repository interfaces and both adapters missing `getByHouseholdPaginated` for Category, Member, Invitation, PersistentTask, Todo.  
**Required Fix:** Add `getByHouseholdPaginated` to all five repository interfaces. Implement in InMemory and SQLite with cursor-based pagination (occurredAt DESC, id DESC).  
**Verification:** Pagination tests pass; `open-household` cost gate stays ≤5 reads; no full scans.

### 4. Sync-Delta Cost Budget Out of Date
**Path:** `src/domain/services/costInstrumentation.ts`  
**Problem:** `sync-delta` budget assumes 8 collections (`reads: 8, writes: 8`). After adding categories and invitations, there will be 10 collections.  
**Evidence:** Comment says "8 collections × pull + push". `SYNC_COLLECTIONS.length` is 8 currently.  
**Required Fix:** Update to `{ reads: 10, writes: 10, networkCalls: 2 }` after adding the two collections.  
**Verification:** Cost gate test updated and passes.

### 5. No Sync Tests for Categories and Invitations
**Path:** `__tests__/domain/v3-06-sync-e2e.test.ts`  
**Problem:** Sync E2E tests cover only `contribution_entries` and `expense_entries`. Categories and invitations have no sync pipeline tests. V4-07 requires "conflicts déterministes" and "tenant isolation" verified for all synced collections.  
**Evidence:** `v3-06-sync-e2e.test.ts` tests pull/push/materialization for contributions/expenses only. `v3-06-groups-invitations-sync.test.ts` tests invitation lifecycle but not sync engine integration.  
**Required Fix:** Add sync E2E tests for categories and invitations: remote delta materializes, local write produces dirty record, push sends to remote, conflict resolution, cross-tenant isolation.  
**Verification:** New sync tests pass; categories/invitations behave identically to contributions/expenses in sync pipeline.

### 6. Cost Gate Tests Don't Cover Category/Todo-Expense Operations
**Path:** `__tests__/domain/cost-gates-v3-08.test.ts`  
**Problem:** The 10 cost gates don't include category CRUD or todo-expense operations. V4-07 requires "cost gate étendu".  
**Evidence:** Gates 1-10 cover open-household, tab-switch, sync-delta, create-contribution, create-expense, classification cache, privacy gate, cost budgets, offline, golden path, accessibility. No gates for category or todo-expense.  
**Required Fix:** Add Gate 11 (category CRUD bounded writes), Gate 12 (todo-expense create/complete bounded writes), Gate 13 (sync-delta with 10 collections within budget).  
**Verification:** Extended cost gate tests pass; all new budgets enforced.

### 7. SQLite Repositories Missing Pagination Implementation
**Path:** `src/infrastructure/repositories/SqliteRepositories.ts`  
**Problem:** SQLite adapters for Category, Member, Invitation, PersistentTask, Todo lack `getByHouseholdPaginated` implementation.  
**Evidence:** Only `SqliteContributionEntryRepository`, `SqliteExpenseEntryRepository`, `SqliteSettlementRepository` implement pagination.  
**Required Fix:** Implement cursor-based pagination in all five SQLite repositories using `LIMIT` + composite cursor (`occurredAt`, `id`).  
**Verification:** Pagination tests pass for both InMemory and SQLite; correct cursor/hasMore behavior.
