## Summary

V4-09 **targeted invitation of an existing named member** is correctly implemented and ready for acceptance.

The feature enables the complete flow specified in `V4_CONSTITUTION.md` §18:
1. Create a group with named members (identities with `userId === null`)
2. From Group Options, tap "Inviter" on a named member → opens Invite screen with `memberId` parameter
3. Invite screen resolves the member, shows a targeted hint, creates an invitation with `targetMemberId`
4. Share the link via native share sheet
5. Recipient opens deep-link `/join/:token`, signs in, accepts
6. Acceptance **links the existing named member** (updates `userId` on the same `memberId`) — no duplicate member is created
7. All historical ledger entries (tasks, expenses, todos, settlements) referencing the original `memberId` remain intact and become naturally associated with the linked account
