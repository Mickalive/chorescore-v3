## 4. Must-fix findings

### F1 — Trusted verification exit 2 (test-file type errors) — `mustFix`
8 TypeScript errors in the new test file (lines 434, 501–505, 730, 870). Fix the test types: `as unknown as`/`as any` for intentionally malformed records, full event shapes or casts for the clean-product records, a valid `DataProcessingPurpose` instead of `'commercial-use'`.

### F2 — Pipeline label contradiction — `mustFix`
`validateNoOperationalIds` (pipeline.ts lines 131–151) lists `label` as a forbidden input field, but `transformContributionCreated` and `transformEntryCreated` **require** `label` for classification. Every contribution/V2-entry fact is rejected at stage 1 (`Operational/free-text field 'label' detected`). The contribution and entry transform paths are **dead code** — this breaks the core acceptance "événements V3 couvrent contributions dépenses settlements usage". Confirmed by 6 jest failures, including `transforms contribution_created correctly` and `transforms V2 entry_created (backward compatible)`.

Fix: allow `label` as pipeline input (consumed for classification, never emitted); rely on output types + gate for the no-free-text guarantee. Add a test proving a labeled contribution transforms successfully with no text in the output event.

### F3 — Gate tests can never pass — `mustFix`
`assessReIdentificationRisk` flags any dataset < 10 records with `re_identification_risk` (high), which blocks approval. The "approves clean product" test (5 records) and "audit log entry is generated" test (empty data) both expect `approved=true` but the gate returns `approved=false` (verified by executing the gate on the exact test data: riskScore 0.7, high violation). Fix the test data (≥10 records with repeated combinations, non-empty data for the audit test) — do not weaken the gate's anti-reconstruction protections.

### F4 — Query budget test/implementation mismatch — `mustFix`
`remainingQueriesThisMinute` expected 1, service returns 2 (`limit - used - 1`). Align test and implementation on one documented semantic.

### F5 — Consent expiry race — `mustFix`
`retentionDays: 0` + strict `<` comparison: when `recordConsent` and `getExpiredRecords` run in the same millisecond (jest), the record is not expired → `expired=0`. Standalone execution with a 1ms gap passes, proving the race. Make deterministic (negative retention, `<=`, or injected clock).

## 5. Non-blocking observations

- **No wiring**: the new `src/analytics` module is not connected to the existing `ResearchAnalyticsGateway` port / `LocalResearchAnalyticsAdapter` (still a no-op). The pipeline is a standalone library; nothing in the operational store emits facts into it. The "asynchrone / incrémentale / checkpointée" aspects are represented only by a passive `PipelineCheckpoint` data structure — there is no checkpoint store, cursor driver, or async batch scheduler. Recommend wiring the adapter → pipeline and adding a real incremental driver in the repair.
- **types.ts header overstatement**: the file header claims "ZERO operational IDs" while `ConsentRecord.userId` and `PipelineCheckpoint.householdId` are operational IDs — defensible as operational-side records (consent/checkpoint), but the invariant text should be clarified.
- **Gate `requiresDifferentialPrivacy`** is computed but never enforced in `validate` approval.
- **`PipelineCheckpoint.id`** uses `Date.now()` + `Math.random()` — non-deterministic; a revision-based deterministic id would be more auditable.
- **V2 preservation claim** could not be verified against `v2-reference` (remote not present in this environment); the module structure matches the V2 architecture described in the constitution §15 and the V3-07 criterion.
