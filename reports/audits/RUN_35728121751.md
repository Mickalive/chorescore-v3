Root cause is history visibility, not ledger or privacy. `src/features/app/demoFixture.ts` seeded:

- `Vaisselle du soir` → `Date.now() - 2d`
- `Courses Migros` → `Date.now() - 1d`

so **Courses** was most recent. The Ajouter history is sorted `occurredAt DESC` (`paginateActivityLog`, `activityLog.ts`). The E2E golden path in `scripts/e2e-android.js:1072` does:

```js
waitFor('Vaisselle du soir', 300000) // visible nodes only, no scroll
```

`waitFor`→`dumpUi`→`findNodes` filters only `content-desc`/`text` nodes that the uiautomator marks visible inside the current viewport. On the `pixel_6` API 35 emulator the second history row is off-screen, so `Vaisselle du soir` never becomes visible → `waitFor` times out → the finalizer job fails even though `npm test`/`privacy:check`/`cost:check` and the `assembleDebug` build are green.

Fix swaps the timestamps with an explicit comment:

```ts
// Most recent contribution: the Ajouter history is sorted by
// occurredAt DESC, so "Vaisselle du soir" must be the first visible
// row for the E2E golden path (waitFor checks visible nodes only).
occurredAt: new Date(Date.now() - 1 * 86400000) // Vaisselle
...
occurredAt: new Date(Date.now() - 2 * 86400000) // Courses
```

and adds regression test `2b` in `__tests__/domain/v3-08-e2e-golden-path.test.ts`:

