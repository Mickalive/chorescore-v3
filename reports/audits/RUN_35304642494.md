## 3. Root cause — proven, not guessed

The workflow's emulator step (`.github/workflows/chorescore-v3-finalize.yml` lines 84–94, identical on `main` and `lab/chorescore-v3`) is:

```yaml
script: |
  set -euo pipefail
  apk=$(find android/app/build/outputs/apk/release -type f -name '*.apk' | head -1)
  adb install -r "$apk"
  npm run e2e:android
```

`reactivecircus/android-emulator-runner@v2` (verified at the **exact v2 tag commit** `a421e43855164a8197daf9d8d40fe71c6996bb0d`):

- `lib/script-parser.js` — `parseScript()` splits the script input on newlines, trims, drops comments/empties → **one entry per line**;
- `lib/main.js` — `for (const script of scripts) await exec.exec('sh', ['-c', script])` → **each line runs in its own `sh -c`**.

Line 1 is `set -euo pipefail`. Ubuntu's `/bin/sh` is **dash**, which does not support `pipefail`:

```
$ sh -c 'set -euo pipefail'
sh: 1: set: Illegal option -o pipefail
$ echo $?   → 2
```

Independent simulation of the action's line-splitting on the workflow's exact script block reproduces the exact finalizer annotation: the step fails at line 1 with exit code 2, before `adb install` and before `npm run e2e:android`. **The E2E script never runs in the finalizer.**

Secondary defect (also simulated): even without the pipefail line, `apk=$(find ...)` runs in its own shell and the variable is lost, so `adb install -r "$apk"` receives an empty path and fails. The multi-line block cannot work under this action regardless of the first line.

**This supersedes the previous cycle's diagnosis** (RUN_35295951364 attributed the failure to transient `uiautomator dump` crashes in the E2E script). The identical exit-code-2 annotation in run 35302658175 proves the script never ran; the dumpUi hardening could not have fixed the finalizer.

## 5. Why the candidate does not meet the criterion

The active criterion is: *fix the concrete trusted finalizer blocker*. The concrete blocker is the **workflow's emulator step script block** (line-splitting + dash `pipefail` → exit 2). The candidate only hardens `scripts/e2e-android.js`, which **never executes** in the finalizer. Applying this candidate and re-running the finalizer would fail again with exit code 2.

The workflow file is trusted-shell owned: AGENTS.md forbids the Builder from modifying workflows, and TASKS.json scope states "Protected control-plane files remain trusted-shell owned". The Builder cannot fix the blocker directly; the next cycle must prepare the Builder-side piece (`scripts/finalizer-e2e.sh`) and the trusted shell must change the workflow to a single-line invocation.
