## 5. Must-fix finding (remains)

### F1 — `scripts/e2e-android.js` requires `CHORESCORE_APK_PATH` that the finalizer never sets ❌

- **Path:** `scripts/e2e-android.js` line 205 (docstring line 14).
- **Problem:** The script's first try-block statement is `if (!apkPath || !fs.existsSync(apkPath)) throw new Error('Unreadable CHORESCORE_APK_PATH: …')`. The trusted finalizer emulator step runs `adb install -r "$apk"` then `npm run e2e:android` **without** setting `CHORESCORE_APK_PATH` (grep of the workflow shows no such env var anywhere). The script's own docstring says the variable is "optional if already installed" — the implementation contradicts the documented contract.
- **Evidence:** line 22 `const apkPath = process.env.CHORESCORE_APK_PATH;`; line 205 guard; workflow lines 84–94 (`script: | set -euo pipefail; apk=$(find …); adb install -r "$apk"; npm run e2e:android`); simulation with the env var deleted reproduces the throw and exit 1.
- **Consequence:** the finalizer would fail at the Android API 35 install/launch/golden-path step, reopen V3-08 again, and the repair objective would not be met.
- **Required fix:** make the APK path optional when the package is already installed — check `pm list packages <packageName>` first and only require/use `apkPath` when an install is actually needed, or auto-locate the APK under `android/app/build/outputs/apk/release/` when the env var is unset.
- **Verification:** in the finalizer environment (no `CHORESCORE_APK_PATH`, package pre-installed), `npm run e2e:android` must reach the golden-path steps; the trusted finalizer must pass the emulator step.
