## 2. The blocker and the repair rationale: SATISFIED

The trusted finalizer run 35692317866 failed at the Android API 35 install/launch/golden-path step. Prior cycles' diagnostics established the concrete root cause with evidence that applies identically to 35692317866:

- A **43 MB release APK** install on the **API 35 x86_64 emulator** (which boots in 5–8 min) takes **3–4+ min**, with **208s observed** in run 35650859523.
- The previous bounds were **120s in `scripts/finalizer-e2e.sh`** and **180s in `scripts/e2e-android.js`** — both **below** the observed device-side duration.
- Finalizer runs **35670332996, 35678248910, 35684869621 and 35692317866** all failed with **2×120s install timeouts and empty output** while subsequent `pm path` / `pm list packages` diagnostics **proved the package WAS present** — the device-side install completed but the `adb` client was killed before it returned.
- The emulator start log also shows `Unable to connect to adb daemon on port: 5037` and the `adb sync` service (used by `adb install`) hangs with zero output on degraded API 35 x86_64 emulators.

The repair addresses each sub-cause with a minimal, documented change:

1. **Headroom (120→300s / 180→300s):** `timeout 300 adb install -r "$apk"` in the wrapper and `ADB_INSTALL_TIMEOUT_MS = 300_000` in the E2E script give **92s headroom** over the 208s observed value and cover the 3–4 min worst case. Two attempts with a 10s inter-attempt sleep remain bounded within the step timeout.
2. **Skip when already present:** `adb shell pm list packages app.chorescore.v3 | grep -q` → `INSTALLED=1` skips re-install. Safe because the emulator is **booted fresh with snapshots disabled** by `reactivecircus/android-emulator-runner@v2`, so the package can only come from a previous install attempt **in this run** — the installed APK is the current build. The E2E script already applied this check; the wrapper now mirrors it.
3. **Conditional adb server restart:** `adb kill-server / start-server / wait-for-device` only before `INSTALL_ATTEMPTS == 1`, not unconditionally before the golden path. This recovers the degraded `adb` sync service (`Unable to connect to adb daemon`) without destabilising a healthy connection before `waitFor('Demarrer')`. Guard verified by `INSTALL_ATTEMPTS" -eq 1[\s\S]*Restarting adb server before install`.
4. **Push + pm fallback via shell transport:** After an `adb install` timeout, the repair tries `timeout 180 adb push "$apk" /data/local/tmp/chorescore-v3.apk` + `timeout 300 adb shell pm install -r /data/local/tmp/chorescore-v3.apk`. The shell transport is more resilient than the sync service on degraded emulators, so a sync-service hang does not fail the finalizer.

Timing simulation:

| Scenario | Result |
|---|---|
| Old 120s bound vs 208s observed install | **TIMEOUT before device completes** → empty output → finalizer fails, package present |
| New 300s bound vs 208s observed | **92s headroom** → install can return success |
| New 300s + push/pm fallback vs sync-service hang | **Fallback succeeds via shell transport** |
| Fresh emulator + skip optimisation | **Skips redundant 43 MB install** when already present from first attempt |

The waitFor still requires elements to appear; the install fix does not skip any golden-path assertion and does not mask a genuinely broken APK (install failures still echo diagnostics and exit 1 after both attempts + fallbacks).

## 6. Findings

All findings are **non-mustFix**.

### 6.1 Exact failure logs not retrievable (non-mustFix)
The diagnostics artifact and step logs from run 35692317866 require admin rights, consistent with prior cycles. The repair is based on the install-duration evidence (208s observed vs 120s bound) and the documented `pm path` proof that applies identically to 35692317866 and the three preceding failures (35670332996/35678248910/35684869621) with the same 2×120s empty-output signature. The next trusted finalizer dispatch will exercise the 300s + fallback path on a real API 35 emulator; the finalizer diagnostic echo (install exit/output, `pm path`, `adb devices`, `df /data`, UI dump XML, logcat) will surface the exact point if the blocker persists.

### 6.2 Skip-install optimisation staleness (non-mustFix)
Skipping install when `pm list packages` already shows the package is safe only because the emulator boots fresh with snapshots disabled, so the package can only be from a previous attempt in this run. The comment and contract test document this precondition. No versionCode staleness check is needed in the finalizer context.

### 6.3 Conditional adb server restart overhead (non-mustFix)
The `kill-server/start-server` before the first install adds ~6–7s overhead even on a healthy emulator. Guarded to attempt 1 only, so the second attempt and the golden path are not delayed. The `adb get-state` health check before install remains, and the E2E script's own `adbReconnect()` still handles degraded transport during dumps.
