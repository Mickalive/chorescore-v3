## Must-fix findings

### 1. Refresh contract still full re-read + full replay; required screen-level delta test missing
`useFocusEffect` → `loadData()` re-reads all five collections and rebuilds the materialized snapshot via `createBalanceSnapshot` (full ledger replay) on every focus. The delta machinery is applied only to settlements created inside the screen; entries added in the Ajouter tab are reflected only through the full re-read. AppContext exposes no data-change signal. The cost-gates test header claims « The Balances screen uses materialized delta refresh, not full re-read » but no test renders the screen — the tests exercise only pure functions and repository call counts. The task explicitly requires a test that renders the Balances screen against a fake repo, adds an entry, and asserts the view updates via delta without a full re-read (or asserts subscription to a data-change signal). **mustFix.**

### 2. Money ledger stale after a settlement in the all-time view
`handleCompenserConfirm` applies the delta only to `snapshotRef.current.contribution`; `moneyByCurrency` is left unchanged (« Money is recomputed on next full load »). Since the all-time money view reads from the snapshot, the Argent block does not reflect the just-persisted settlement until the next focus/remount. Independently verified: after a 15-min/CHF 5.00 settlement (rate 60 min = CHF 20), the screen shows money a=−1500/b=+1500 while true ledger replay is a=−1000/b=+1000. The screen also discards the settlement entity returned by `repos.settlements.create` and stores fake ids (`pending-<ts>` / `sett-<ts>`), so in-session state never matches the persisted ledger entry. **mustFix.**
