## Must-fix findings (independent execution against the compiled domain)

### 1. Money precondition sign inversion — `settlementPreconditions.ts`

`checkMoneyDebtSufficient` computes `availableDebt = -counterpartyMoneyBalance` and requires it ≥ the settlement amount, i.e. it requires the counterparty to **owe** money. Per the entity doc and the accepted baseline test (`ledgers.test.ts` — "a settlement updates both ledgers…"), the counterparty is the member **owed** money (positive balance); the settlement reduces the creditor's debt and the counterparty's receivable.

Demonstrated: a has 15 min credit, a owes b (a −1500, b +1500). A valid settlement of 15 min / 500 CHF returns `valid=false` with `"Counterparty b owes -1500 CHF minor units, but settlement requires 500"`. The same scenario is applied correctly by the accepted baseline ledger test.

### 2. Sequence over-settlement not detected — `validateSettlementSequence`

`appliedSettlements` is pushed but never read; every iteration recomputes balances from raw contributions/expenses with an empty settlement list. Demonstrated: a has 15 min credit; s1 consumes 15, s2 consumes 15 → `valid=true` (30 consumed against 15 available). The existing sequence test passes only because its first settlement fails the inverted money check — it never exercises accumulation.

### 3. Replay accepts rate-inconsistent settlements — `contributionLedger.ts` / `expenseLedger.ts`

The replay validators check structure only (members, positive amounts, unit/currency match) but never that `moneyAmountMinor` matches the snapshotted rate quote. Demonstrated: a settlement with 15 min / 499 CHF under a 60 min = 2000 CHF rate is rejected by `validateCrossLedgerSettlement` but silently replayed by both ledger calculations, applying the wrong amount. This fails the task objective "make replay robust against malformed settlements".

### 4. Tests encode inverted semantics / false positives — `validation-preconditions-periods.test.ts`

The "valid settlement" test uses a counterparty with negative balance (contradicting the accepted baseline semantics); the "sequence catches over-settlement" test passes for the wrong reason (inverted money check on s1). No test covers replay rejection of rate-inconsistent settlements. These tests must be rewritten to the correct semantics and must actually exercise accumulation.
