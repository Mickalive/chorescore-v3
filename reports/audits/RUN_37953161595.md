## Findings

### Finding: ANR detection heuristic fixed (scripts/e2e-android.js)

| Field | Value |
|-------|-------|
| **Path** | `scripts/e2e-android.js` |
| **Problem** | The previous heuristic `isAppAnr = !title.includes('System UI')` misclassified launcher ANRs (`"Quickstep isn't responding"`, `"System UI isn't responding"`, `"Process system isn't responding"`, `"com.android.phone isn't responding"`) as app ANRs. This caused the E2E script to force-stop the healthy ChoreScore app every ~90s during cold start, resetting native-library load from zero. The app never reached Groups within the 1260s window. |
| **Evidence** | Trusted finalizer run 37946700758 failure; code comment in current `e2e-android.js` lines 512–518 documents the root cause. |
| **Must Fix** | No — already fixed in candidate. |
| **Required Fix** | Detection now checks for `"ChoreScore"` label or package name `app.chorescore.v3`. Infra ANRs re-assert app foreground via `am start` without force-stop, allowing cold start to continue uninterrupted. `dismissAnrOverlay()` is also called in `findVisible()` and `findByTestId()` before scrolling, so infra ANR dialogs covering the app are dismissed before lookups fail. |
| **Verification** | Trusted verification passed; all gates green; Android debug build successful. |
