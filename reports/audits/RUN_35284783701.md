### F1 — `waitFor('Contribution', { … })` passes an options object as the timeout → golden path guaranteed to fail

- **Path:** `scripts/e2e-android.js` line 287.
- **Problem:** `waitFor('Contribution', { exact: false, scroll: true, waitMs: 500 })` passes an options object as `timeoutMs`. `waitFor(label, timeoutMs = 10000)` computes `until = Date.now() + timeoutMs`, which string-concatenates to `<timestamp>[object Object]`; `Date.now() < until` is then always `false`, the polling loop never executes, and the function **throws `Timed out waiting for Contribution` immediately** regardless of app state. The golden path E2E — a V3-08 acceptance criterion and the trusted finalizer's last step — is **guaranteed to fail at step 6** in the real emulator environment. The finalizer would fail, reopen V3-08, and the repair objective (make the trusted finalizer pass) would not be met.
- **Evidence:** line 287 vs signature line 175; node reproduction confirms `until` is a string and the comparison is always false; all other 10 `waitFor` calls pass numeric timeouts; mocked-adb simulation of the candidate reaches this line and throws. The same line exists in the pristine tree (line 258) — pre-existing, never reached by previous audits because the APK guard threw first; the candidate's fix now exposes it.
- **Required fix:** pass a numeric timeout, e.g. `waitFor('Contribution', 15000)`. Keep the APK-path repair intact.
- **Verification:** with the fix, `npm run e2e:android` must reach `writeResult('pass')` and exit 0 in the finalizer emulator (no `CHORESCORE_APK_PATH`, package pre-installed); the trusted finalizer must pass the Android API 35 install/launch/golden-path step.
