## 4. Technical soundness of each change

**`withTimeout` (45 s):** Correctly races promise vs timer with `settled` guard, clears timer on early settlement, handles both resolve and reject via `promise.then(onResolve, onReject)` so no unhandled-rejection warning, and ignores late settlement. 45 s is generous vs healthy <1 s open yet far below the 600 s Démarrer window (worst case before window ~70 s + 45 s still <120 s). Late handle discard is the same lifecycle as previous `catch→null` path; no new leak class.

**Fallback semantics:** Existing fallback was `catch→null → inMemory`. New fallback is `timeout→null → inMemory`. Both reuse the same transactional `createInMemoryRepositories()` path with `MaterializingSyncState`, snapshot/restore, sync recording wrappers — no ledger or sync invariant change. On healthy devices SQLite still wins; on degraded CI the app becomes testable instead of hung. This is resilience, not masking: golden-path still asserts reaching Démarrer/Appartement/Ajouter/Balances/À faire.

**Diagnostic echoes:** Failed dumps never cached (`dumpUi` returns empty without setting `_dumpCache`), so timeout echo always attempts a fresh dump. `finalizer-e2e.sh` echo loops are best-effort (`cat` guarded by `[ -f ]`), do not affect exit code, and are bounded (`tail` for logcat, full cat for XMLs which are small). No PII: UI nodes contain only labels like Ajouter/Balances, not operational IDs.

**Tests:** Not weak. `withTimeout` tests cover all branches including the subtle late-resolution case with `resolveLate` and `setTimeout 10 ms` to detect unhandled rejection. Wrapper echo tests assert both the `UI dump at timeout` string and `content-desc` filtering, and the `audit/android-e2e/*.xml` path — static contracts preventing regression to silent failure.
