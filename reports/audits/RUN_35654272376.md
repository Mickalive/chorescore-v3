## 3. Root-cause analysis: the candidate's hypothesis is disproven

The candidate assumes `router.push('/add')` broke the golden path (tabs never appeared after tapping "Appartement"). Independent verification with the **exact Expo Router 57.0.22 resolution pipeline** shows the opposite:

### 3.1 How `router.push` resolves a string href

`router.push(href)` → `linkTo` → `getNavigateAction` → `store.linking.getStateFromPath(href, store.linking.config)` (verified in `node_modules/expo-router/build/global-state/getNavigationAction.js` and `store.js`). The linking config is built by `getLinkingConfig`/`getReactNavigationConfig` from the real route tree.

### 3.2 Real route tree (generated, not assumed)

`getRoutes` over the actual app directory produces:

```
(root) [layout]
  index [route]
  group-options [route]
  invite [route]
  _sitemap [route]
  +not-found [route]
  join/[token] [route]
  (tabs) [layout]
    add [route]
    balances [route]
    todos [route]
```

### 3.3 Empirical path resolution (exact config structure)

| Path | `getStateFromPath` result | Meaning |
|---|---|---|
| `/add` | `__root → (tabs) → add` | **Valid** — navigates to the Add tab with the tab bar |
| `/(tabs)` | `+not-found` (params `not-found: ["(tabs)"]`) | **Unmatched Route screen** — the group path is not a matchable URL (the `(tabs)` group has no `index` child) |
| `/` | `__root → index` | Groups list |
| `/balances` | `__root → (tabs) → balances` | Valid |
| `/todos` | `__root → (tabs) → todos` | Valid |

`shouldAppendNotFound()` returns true (app.json sets no `router.notFound=false`; no `app/+not-found` file), so the `+not-found` route renders `RootUnmatched` ("Unmatched Route").

### 3.4 Consequence

With the candidate's change, tapping "Appartement" would render the **Unmatched Route** screen. The E2E golden path would then fail **deterministically** at `waitFor('Ajouter', 300000)` — the exact failure mode the candidate claims to fix, now guaranteed by code instead of emulator flakiness. The pristine `/add` route is correct.

## 7. Findings

- **Evidence:** `getStateFromPath('/(tabs)')` → `{"routes":[{"name":"+not-found","params":{"not-found":["(tabs)"]},"path":""}]}`; `getStateFromPath('/add')` → `__root → (tabs) → add`. `shouldAppendNotFound()` true. Git history: `/(tabs)` was the pre-e993606 state flagged as broken in RUN_35138202361.md.
- **Required fix:** Revert the candidate line — keep `router.push('/add')` (with `setCurrentHouseholdId(id)`), matching the pristine accepted baseline.
- **Verification:** `git diff` vs pristine must be empty for `app/index.tsx`; route-resolution test must show `/add` → `(tabs)/add` and `/(tabs)` → `+not-found`.

### 7.2 MUST-FIX — the actual trusted finalizer blocker is not repaired

- **Problem:** The candidate does not address the real emulator-step failure (17+ consecutive finalizer emulator failures). The `/add` route was never the cause; the concrete blocker (boot/install/cold-start/dump fragility or app runtime crash) remains unidentified.
- **Evidence:** Run 35650859523 step 7 failed after 20m59s with all gates and the x86_64 build passing; step-7 logs (403) and diagnostics artifact (401) not readable from this environment; RUN_35414682827.md documents every actual finalizer run failing at the emulator step.
