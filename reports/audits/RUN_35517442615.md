## 4. Technical soundness of the repair

**Shared parser (sound):** `parseNodesFromXml(xml)` is a pure extraction of the parsing loop previously inline in `dumpUi()` — identical regex (`/<node\b([^>]*)\/?>(?:<\/node>)?/g`), identical attribute extraction with `decode()`, and the same `!xml || !xml.includes('<node')` guard that `dumpUi()` already applied before reaching the loop. `dumpUi()` behavior is unchanged (verified by source comparison and the full test suite). The warm-up block now calls the same function, so the cache is populated with real nodes using exactly the same logic as a real dump.

**Cache interaction (fixed):** The warm-up dump happens at the end of `launch()` after the app is in foreground (dumpsys poll + pidof check). When the Demarrer screen is captured, the parsed cache lets `waitFor('Demarrer')` match immediately — no 30s dead spin, no first real dump. When the app is still on a splash screen at warm-up, the cache simply doesn't match and the loop falls through to a real dump after TTL expiry — strictly no worse than before. `tapNode()`/`swipeUp()` still invalidate the cache on screen transitions, so no stale-match risk across transitions. The post-launch `screenshot('diagnostic-post-launch')` reuses the warm-up cache (now with real nodes) — diagnostic-only, no pass/fail impact.

**Test quality (effective):** The updated warm-up test asserts the actual repair mechanism — `warmupNodes[\s\S]*_dumpCache\s*=\s*\{.*xml.*warmupXml.*nodes.*warmupNodes` and `parseNodesFromXml(warmupXml)` — and the new test asserts `function parseNodesFromXml(`, `function dumpUi[\s\S]*parseNodesFromXml\(xml\)`, and `parseNodesFromXml\(warmupXml\)`. Reverting the fix (empty nodes array, inline parsing, or warm-up without parsing) fails every assertion. Consistent with the file's established static-contract style (18 tests, all static). Not weak tests.

**Timing budget:** The fix adds zero adb calls (warm-up block remains rm + dump 60s/1 attempt + cat 30s/1 attempt, ~91s worst case, try/catch best-effort). It strictly reduces golden-path time in the common case: the first `waitFor('Demarrer')` returns immediately from the parsed cache instead of spinning 30s + dumping 30-60s. Total worst case ≈ 40.5 min, within the 360-min job timeout and the failed run's 31m47s.
