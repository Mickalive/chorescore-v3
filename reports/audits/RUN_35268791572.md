## 4. Must-fix findings

### F1 — Syntax error breaks typecheck (trusted gate)
- **Path:** `__tests__/domain/cost-gates-v3-08.test.ts:205`
- **Problem:** unescaped apostrophe in `doesn't` inside a single-quoted `describe()` string → TS1005/TS1002/TS1128 at lines 205-260. This is the trusted verification failure (exit 2).
- **Required fix:** escape the apostrophe (`doesn\'t`) or reword (`does not`).
- **Verification:** `npm run typecheck` exits 0.

### F2 — Wrong import path in accessibility.ts
- **Path:** `src/ui/accessibility.ts:14`
- **Problem:** `'../design-system/theme'` resolves to `src/design-system/theme` (nonexistent); the file is at `src/ui/accessibility.ts`, so the correct path is `'./design-system/theme'`. Typecheck still fails after F1 is fixed.
- **Required fix:** `import { typography, colors } from './design-system/theme';`
- **Verification:** `npx tsc --noEmit` exits 0.

### F3 — Gate 10 test is self-contradictory
- **Path:** `__tests__/domain/cost-gates-v3-08.test.ts` (Gate 10)
- **Problem:** asserts `theme.ts` content does not contain `'terracotta'`, but the file's own comment says "No warm terracotta…". Fails at runtime once F1+F2 are fixed (verified: 424/425 pass, this is the only failure).
- **Required fix:** scan for actual token usage (e.g. no `terracotta:` color key / warm hex values in the parsed theme) or reword the comment; the V3 design system (graphite/off-white/metallic, forest green/wine red only) must remain clean.
- **Verification:** `npm run test` exits 0 with Gate 10 still proving no warm V2 tokens.

### F4 — Golden path claims compensation coverage but never creates a settlement
- **Path:** `__tests__/domain/cost-gates-v3-08.test.ts` (Gate 9) + `__tests__/domain/v3-08-e2e-golden-path.test.ts`
- **Problem:** Gate 9 title and release notes claim the golden path covers "compensate", but neither new test file ever calls `repos.settlements.create` — only `getByHousehold` with empty arrays. The V3-08 objective explicitly requires E2E scenarios covering compensation.
- **Required fix:** add a real settlement step: create a `CrossLedgerSettlement` with a `rateSnapshot`, then assert both ledgers remain zero-sum and the settlement's effect on contribution/money balances is applied.
- **Verification:** golden path passes with the settlement step; both ledgers zero-sum after settlement.
