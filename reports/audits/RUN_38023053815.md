## Summary

V4-09 **repair for the trusted finalizer failure in run 38021535805** is complete and verified.

The failure was an **infrastructure flakiness**, not a product bug: on the unaccelerated API 35 x86_64 emulator, `system_server` was tombstoning and SystemUI crashed ("crashed too many times, killing!"). A single coordinate tap on "Créer un groupe" was silently dropped — `setShowCreate()` never ran, the inline create form never rendered, and the golden path failed later at `groups.nameInput` with an unchanged screen dump.

The repair hardens the E2E golden path against this class of transient infra failure **without weakening any assertion**:

1. **Stable testID** — `app/index.tsx` adds `testID="groups.createButton"` to the primary create action.
2. **Button forwards testID** — `src/ui/components/Button.tsx` accepts and forwards `testID` to the native `TouchableOpacity` (resource-id), so the E2E driver can target the control directly instead of a localized label.
3. **Retrying helper with polling** — `scripts/e2e-android.js` introduces `openCreateGroupForm()` which:
   - Drives the stable `groups.createButton` testID
   - Retries the tap, clearing any transient infra ANR overlay between attempts
   - Polls for the real form field (`groups.nameInput`) until it appears or a 240s timeout
   - Falls back to the localized label for any build where the testID is absent
   - **Does NOT weaken the assertion**: the form (and therefore the field) must still open or the golden path fails.
4. **Test coverage** — `__tests__/domain/v3-08-finalizer-wrapper.test.ts` adds a test verifying the stable testID, the retrying helper, and the removal of the old fragile pattern.

The old non-waiting pattern `tapLabel('Créer un groupe') + waitFor('Créer')` is gone — it matched the button itself and never actually waited for the form.
