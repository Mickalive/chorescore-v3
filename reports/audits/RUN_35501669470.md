## 4. Technical soundness of the fix

**Status discrimination (sound):** `execFileSync` throws with `err.status` set to the child's exit code. Android toybox `pidof` exits 1 with empty stdout when no process matches — the exact crash signal. The `adb()` wrapper retries 3× (2s sleeps on non-timeout) then rethrows `lastError`, preserving `err.status`, so the `waitFor()` catch reliably sees `status === 1` for a dead app and `status === null`/killed for transport timeouts. Verified by simulation of both paths.

**Relaunch branch (complete):** matches the prescribed sequence — invalidate dump cache, force-stop, monkey relaunch, sleep 15s, continue. All adb sub-commands are wrapped in try/catch so a degraded transport cannot crash the loop.

**Transport fall-through (sound):** non-status-1 errors proceed with the normal wait; the `adb()` wrapper has already logged each failed attempt, and the existing dump-failure detection (3 consecutive failures → `adbReconnect()`) handles degraded transport. The acceptance criterion "other pidof errors (transport) are logged and the normal wait continues" is satisfied.

**Test strengthening (effective):** the new test asserts the error-status handling itself (`catch (err)`, `err.status === 1`) and the reachability of the relaunch path from the status-1 branch. Reverting to the old `catch (_) { /* pidof failed — proceed with normal wait */ }` fails every assertion (`catch (err)`, `err.status === 1`, `pidof exit 1`, `Transport or other adb error` all disappear). The feature cannot silently regress to dead code.
