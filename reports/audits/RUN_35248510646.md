## Must-fix findings

### 1. Typecheck failure — missing import of `ScopedContributionRepository`/`ScopedExpenseRepository`

- **Path:** `__tests__/domain/v3-06-repair-sync-authorization.test.ts` (import block lines 20–23; usages at 637, 652, 672, 687, 707, 724, 745)
- **Problem:** The import was trimmed to only `createScopedRepositories`, but the "authorization enforced through repository path" describe block still instantiates `new ScopedContributionRepository(...)` / `new ScopedExpenseRepository(...)`. Both classes are still exported from `ScopedRepositoryFacade.ts`.
- **Evidence:** Trusted log exit code 2 with 7 TS2304 errors; independent `tsc` reproduces them; independent jest shows 7 `ReferenceError: ScopedContributionRepository is not defined` failures.
- **Required fix:** Restore the import (or rewrite the 7 tests to use `createScopedRepositories`), then re-run `tsc` and the full suite.

### 2. Failure-injection test broken — spread of class instance loses prototype methods

- **Path:** `__tests__/domain/v3-06-repair-sync-authorization.test.ts` lines 972–978, assertion at 1013
- **Problem:** `{...originalContributions}` copies only own enumerable fields (`inner`, `syncState`); all prototype methods (`getById`, …) are lost. `materializeDeltas` → `upsertWithConflictResolution` calls `repos.contributions.getById(record.id)` **before** `seed` (SyncMaterializer.ts line 213), so the error is `repos.contributions.getById is not a function` instead of the intended `Simulated materialization failure`. The test fails and does not prove the intended scenario.
- **Evidence:** jest failure: `Expected substring: "Simulated materialization failure" / Received string: "repos.contributions.getById is not a function"`.
- **Required fix:** Inject via `Object.create(originalContributions)` with overridden `seed`/`create` (or a Proxy) so the prototype chain is preserved and the intended error path is exercised; keep the cursor + all-tables-unchanged assertions.

### 3. SQLite factory-wiring test broken — raw sync state passed to `pullDeltas`

- **Path:** `__tests__/infrastructure/repositories.test.ts` lines 1013–1105 (pull at 1064, assertion at 1075)
- **Problem:** The test passes the raw `SqliteSyncStateRepository` to `pullDeltas` instead of a `MaterializingSyncState` wrapping it, unlike the factory (RepositoryFactory.ts lines 441–442). Raw SQLite `applyDeltas` is buffer-only (SqliteRepositories.ts lines 1168–1201), so the remote delta never materializes into the business table.
- **Evidence:** jest failure at line 1075 (`entry` is null). The objective explicitly requires "raw SQLite repos + SyncRecording* wrappers + MaterializingSyncState" or an exported testable factory path.
- **Required fix:** Wrap `baseSyncState` in a `MaterializingSyncState` (export the class or replicate the wiring) and pass the wrapped state to `pullDeltas`; keep the remote→business, local→dirty, push assertions.
