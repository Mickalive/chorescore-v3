## Why this is not accept

Per instructions: *"A nonzero trusted verification exit code is mandatory mustFix and decision MUST NOT be accept."* Here exit is 1, so `accept` is forbidden regardless of all other gates passing.

## Root cause — blocker 1: expo install --check (Builder-fixable)

The trusted finalizer's `Trusted product, privacy and cost gates` job runs:

```sh
npx --no-install expo install --check
```

That command exits 1 when installed versions lag expected versions for the installed `expo` SDK. The current `package.json` pins `expo ~57.0.19` etc., but the resolved `expo@57.0.23` etc. are now behind the latest patch for SDK 57. Aligning `package.json` (e.g., `npx expo install --fix`) is the standard Builder repair for this gate.

## Root cause — blocker 2: emulator script splitting (trusted-shell only)

`.github/workflows/chorescore-v3-finalize.yml` lines 90-94 on both `HEAD` and `main` still:

```yaml
script: |
  set -euo pipefail
  apk=$(find android/app/build/outputs/apk/release -type f -name '*.apk' | head -1)
  adb install -r "$apk"
  npm run e2e:android
```

`reactivecircus/android-emulator-runner@v2` does not run this as one shell. `lib/script-parser.js` splits on newlines; `lib/main.js` runs each via `exec.exec('sh', ['-c', script])`. On Ubuntu `/bin/sh` is dash:

- `sh -c 'set -euo pipefail'` → `sh: 1: set: Illegal option -o pipefail` → exit 2
- `bash -c 'set -euo pipefail'` → exit 0

The wrapper `scripts/finalizer-e2e.sh` already solves this by running as a single `bash` process, but the workflow never invokes it. This is the identical failure of runs 35293489693, 35302658175 and 35315519533 documented in `RUN_35317911890`.

Workflows are protected control-plane files the Builder cannot edit (`AGENTS.md`). The required change is `script: bash scripts/finalizer-e2e.sh` on `main`, then a finalizer re-run.
