## Summary

The repair fully resolves the single must-fix finding from RUN 35187808657 / RELEASE_STATUS. Completion is now executed as a single atomic operation through `completeTodoAtomic`, with a storage-level transaction (`withTransaction`) for both SQLite and in-memory paths. UI calls the single operation; `Promise.all` removed. Four failure-injection tests prove rollback on either side and idempotent retry.

## What changed (candidate diff)

- **New:** `src/application/use-cases/completeTodoAtomic.ts` — validates via `planTodoCompletion` then `await repos.withTransaction(() => { todos.update; contributions.create })`. Throws on validation or any write failure, rolling back atomically.
- **Repo contract:** `src/infrastructure/repositories/RepositoryFactory.ts` — `AllRepositories.withTransaction<T>` added. SQLite path uses `db.withTransactionAsync`; in-memory path snapshots `InMemoryTodoRepository` and `InMemoryContributionEntryRepository` and restores on throw.
- **In-memory support:** `src/infrastructure/repositories/InMemoryRepositories.ts` — `snapshot()/restoreFromSnapshot()` for todo and contribution repos (deep copy of `beneficiaryMemberIds`).
- **UI:** `app/(tabs)/todos.tsx` — imports `completeTodoAtomic`, `handleComplete` now `await completeTodoAtomic(repos, {...})` with comment about atomic commit/rollback; `Promise.all` removed.
- **Tests:** `__tests__/domain/todo-completion.test.ts` — three former success tests rewritten to use `completeTodoAtomic`; new `describe('Atomic completion failure injection')` adds (a) todo-update failure → 0 entries & todo stays `todo`, (b) contribution-create failure → todo rolled back, (c) retry after contribution failure → exactly 1 entry, (c2) retry after todo-update failure → exactly 1 entry.
- **Cost gate:** `__tests__/domain/cost-gates-v3-05.test.ts` now imports and exercises `completeTodoAtomic`.
- **Test-infra fix:** `__tests__/infrastructure/repositories.test.ts` adds `withTransaction: async fn=>fn()` to manual repo stub.
