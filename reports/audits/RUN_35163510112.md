## Summary

The candidate repairs all four must-fix findings from audit RUN_35158693615:

1. **Equal-timestamp pagination gap** — composite cursor `{ o: occurredAt, i: id }` with `ORDER BY occurredAt DESC, id DESC` and predicate `(occurredAt < c.o OR (occurredAt = c.o AND id < c.i))` in both InMemory and SQLite repositories (contributions, expenses, settlements) and in `paginateActivityLog`. New test seeds PAGE_SIZE+5 entries with one identical `occurredAt` plus older entries and asserts every seeded id is reachable exactly once across pages.
2. **'Charger plus' race** — `loadHistory` is guarded by an in-flight ref that skips a concurrent load-more call, and the append step dedupes by entry id. New test fires two concurrent load-more calls and asserts no duplicate ids.
3. **Share/history unit mislabeling** — the share message and the history row display now use the entry's stored `unit` (`e.unit === 'minutes' ? 'min' : 'pts'`) instead of the current household unit, so historical entries keep their original unit label after a Minutes↔Points switch (§18).
4. **Custom-split submit not blocked** — the submit button is disabled when `sum(customShares) != amountMinor` (memoized `customSplitValidation`) and `submitExpense` early-returns on mismatch, so an invalid custom-split expense can never be persisted.

## Objective verification

### 1) Composite cursor (Finding 1)
- `InMemoryRepositories.ts`: contributions (lines 212-232), expenses (355-375), settlements (426-446) sort by `occurredAt DESC, id DESC`, apply the composite cursor predicate, and emit `JSON.stringify({ o, i })` cursors.
- `SqliteRepositories.ts`: contributions (393-408), expenses (775-790), settlements (944-959) use `AND (occurredAt < ? OR (occurredAt = ? AND id < ?))` with `ORDER BY occurredAt DESC, id DESC LIMIT ?` and the same composite cursor encoding.
- `paginateActivityLog` (activityLog.ts) uses the identical composite cursor and id tie-break, keeping the merged stream consistent with the per-repo streams.
- New test `entries with identical occurredAt spanning PAGE_SIZE boundary are all reachable` seeds 20 entries sharing one timestamp + 5 older, pages until `hasMore=false`, and asserts all 25 seeded ids are found exactly once (30 total with older entries).
- **Independent check:** a standalone simulation of both the InMemory algorithm and the SQLite algorithm over 50 fuzz trials (random sizes 1-200, limits 1-30, 1-5 distinct timestamps) plus the equal-timestamp boundary scenario and the merged-stream scenario: **no missing ids, no duplicates in any trial** (see `/tmp/opencode/verify_cursor.js`).

### 2) Concurrent load-more guard (Finding 2)
- `loadHistoryInFlightRef` is set before the fetches and cleared in `finally`; a second `loadHistory(true)` while one is in flight is skipped (`if (loadMore && loadHistoryInFlightRef.current) return;`).
- The append step additionally dedupes by entry id (`existingIds` set per repo), covering any residual duplicate path.
- New test `concurrent load-more calls do not duplicate entries (in-flight guard)` simulates two concurrent fetches with the same cursor and asserts the merged list has no duplicate ids and exactly PAGE_SIZE+PAGE_SIZE entries.

### 3) Entry unit in share + history row (Finding 3)
- `handleShare`: `const entryUnitLabel = e.unit === 'minutes' ? 'min' : 'pts';` — the message uses the entry's stored unit.
- History row: `${(entry.entry as ContributionEntry).value} ${(entry.entry as ContributionEntry).unit === 'minutes' ? 'min' : 'pts'}` — same fix.
- The contribution form still uses the current household unit for new entries (`Valeur ({unitLabel})`), which is correct: only historical display/share must preserve provenance.

### 4) Custom-split submit blocked (Finding 4)
- `customSplitValidation` memo computes `totalShares` vs `amountMinor`; the submit Button is disabled when `eForm.splitMode === 'custom' && !customSplitValidation.valid`.
- `submitExpense` early-returns when `totalShares !== amountMinor` (write-time guard), so even a programmatic call cannot persist an invalid custom-split expense.
- The inline error text is preserved and now driven by the same memoized validation.
