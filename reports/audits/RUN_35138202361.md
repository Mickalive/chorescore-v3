## Must-fix findings

### 1. `package.json` — nonexistent `expo-sqlite@~57.0.4` (trusted verification failure)
- **Problem**: npm ETARGET; install aborts; nothing else can be verified. Lockfile not regenerated.
- **Evidence**: TRUSTED log exit 1; `npm view expo-sqlite dist-tags.sdk-57` = `57.0.3`; `grep -c expo-sqlite package-lock.json` = 0.
- **Required fix**: pin `~57.0.3` and regenerate `package-lock.json`.

### 2. `app/index.tsx:181` — TS1382 bare `>` in JSX text
- **Problem**: typecheck gate fails.
- **Required fix**: `{'>'}` or `&gt;`.

### 3. `app/(tabs)/add.tsx:80,91` — `variant="tabLabel"` not in Text Variant union
- **Problem**: TS2322; typecheck gate fails.
- **Required fix**: add `'tabLabel'` to the Variant union in `src/ui/components/Text.tsx` (or use an existing variant).

### 4. `app.json` — missing `assets/icon.png`
- **Problem**: `expo prebuild --platform android` fails with ENOENT; the Android native build path required by the trusted pipeline is blocked.
- **Required fix**: add a real icon asset (and any other referenced assets).

### 5. `src/features/app/AppContext.tsx` — local-first storage not wired
- **Problem**: AppContext instantiates only `InMemoryRepositories`; `SqliteStorage` (indexed schema) and `SqliteRepositories` are dead code never imported anywhere. All business data lives in memory and is lost on restart. The V3-02 acceptance "données métier nombreuses dans un stockage local indexé plutôt que gros tableaux JSON" and the objective "Le stockage métier devient local-first et indexé, de préférence via expo-sqlite" are not met by the running app.
- **Evidence**: grep for `SqliteRepositories`/`SqliteStorage` matches only inside those two files; `AppContext.tsx` imports only in-memory repositories.
- **Required fix**: wire the SQLite repositories into AppContext (in-memory fallback for tests) so business data actually persists in the indexed local store.

### 6. `app/index.tsx` — root Groups screen cannot open the selected group
- **Problem**: `openHousehold(id)` ignores `id` and always pushes `/(tabs)`; `currentHouseholdId` stays pinned to `DEMO_HOUSEHOLD_ID` after sign-in. Tapping any group card opens the demo household's data; a newly created group can never be opened.
- **Required fix**: set `currentHouseholdId` to the tapped group's id before navigating.
