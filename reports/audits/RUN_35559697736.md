## 2. What the fix does

The stuck-app detector in `waitFor()` force-stopped and relaunched the app after `STUCK_APP_THRESHOLD=4` consecutive real dumps with no label match. On a loaded API 35 x86_64 emulator, each uiautomator dump takes 30-60s, so 4 empty dumps = 2-4 minutes — while the documented React Native cold start can reach 240s. The detector could therefore kill a healthy app mid-cold-start, resetting the cold start each cycle (an infinite kill loop), which matches the 15 consecutive finalizer emulator-step failures.

The fix implements the **time-based stuck detection** option prescribed in the task:

1. `COLD_START_GRACE_MS = 300_000` (5 min) — beyond the documented 240s worst case, within the 600s `Demarrer` timeout.
2. `waitFor(label, timeoutMs, { graceMs = 0 })` — new optional parameter.
3. During the grace period, successful-but-empty dumps do **not** increment `consecutiveEmptyMatchCount`; they log progress (`COLD-START GRACE: …s elapsed … app alive`) so the step logs show cold-start progress.
4. After the grace period, the counter increments normally and the stuck detector fires as before.
5. The `Demarrer` wait (the first wait after launch, covering cold start) passes `graceMs: COLD_START_GRACE_MS`.
6. The pidof crash detector (every 30s) remains active during the grace period — a genuinely crashed app is still relaunched.
