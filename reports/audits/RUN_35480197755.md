## 5. Technical soundness of each change

1. **Dump cache (2s TTL)**: inert in the slow-emulator scenario it targets (TTL < dump duration, so the cache expires before the next call); on fast emulators it can return stale pre-swipe dumps across `findVisible` scroll iterations, but no golden-path element requires scrolling (Demarrer, Appartement and the three tab labels are all on the first dump). It cannot cause a false PASS in this golden path: `waitFor` loops only ever see stale *negative* results for at most ~2s, and the final `writeResult('pass')` is preceded by fresh dumps. Latent issue recorded as an informational finding.
2. **Scroll 7→3**: sufficient for this golden path; all `findVisible` targets are near the top of the screen or in the persistent tab bar.
3. **dumpsys pre-check**: weak (the package name can appear in `dumpsys activity` output even when not the foreground activity) but non-fatal; the real gate is `waitFor('Demarrer')`.
4. **Demarrer 480s**: strictly more tolerant than the baseline 360s; the step ran 22.3 min in the failed run, so the +2 min worst case stays well within the job timeout.
5. **Settle 30s→15s**: saves 15s; the dumpsys poll provides the headroom.
