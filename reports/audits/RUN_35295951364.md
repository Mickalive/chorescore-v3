**Root cause:** `dumpUi()` swallows `uiautomator dump` errors (`try { shell('uiautomator', 'dump', ...) } catch (_) {}`) but then **unconditionally** runs `adb(['exec-out', 'cat', '/sdcard/chorescore-window.xml'])`. When the dump fails transiently — a well-known emulator behavior (e.g. `ERROR: could not get idle state` during UI transitions/animations) — the dump file is never created, `exec-out cat` exits non-zero, and `execFileSync` throws, crashing the entire E2E script with an unhandled adb error at the first `waitFor`/`findNodes`/`findVisible`/`assertAbsent` call.
