## Findings

### 1. Balances history rows are non-interactive (must-fix)

**Path:** `app/(tabs)/balances.tsx` (lines 894–917)

**Problem:** The `historyRow` renders `formatActivityRow` as a `Text` component with `numberOfLines={2}`. No `onPress`, no action buttons, no navigation to edit, no delete confirmation, no share invocation.

**Evidence:**
```tsx
{historyPage.entries.map((entry) => (
  <View key={entry.entry.id} style={styles.historyRow}>
    <Text variant="body" style={styles.historyText} numberOfLines={2}>
      {formatActivityRow(entry, memberName, unitLabel, t('add.settlement'))}
    </Text>
  </View>
))}
```

**Required Fix:** Make each history row pressable. On press, show an action sheet (or modal) with **Edit**, **Delete**, **Share**.
- **Edit:** Navigate to edit screen (reuse `add.tsx` with edit mode or new screen) pre-filled with the entry's data.
- **Delete:** Show confirmation alert (`t('add.deleteConfirm')`), call `repos.contributions.delete(id)` or `repos.expenses.delete(id)`, emit `dataChange` for delta refresh.
- **Share:** Call `services.share.share({ message: formattedLine })` using existing `share.taskLine` / `share.expenseLine` keys.

Must preserve paginated loading, delta refresh, and zero-sum invariants.

**Verification:** Manual test — open Balances → Activity → tap a task row → action sheet appears → Edit opens pre-filled form → Save updates entry and balances refresh via delta. Delete confirms → entry removed, balances update, zero-sum holds. Share opens native sheet with formatted text.

### 2. Add screen lacks edit mode (must-fix)

**Path:** `app/(tabs)/add.tsx`

**Problem:** Translation keys `add.editBanner`, `add.update`, `add.errorEdit`, `add.errorDelete` exist but no edit logic is implemented. The screen only supports creation.

**Evidence:** No edit mode state, no pre-fill from existing entry, no update submission path. The form resets after submit but never loads an existing entry.

**Required Fix:** Add edit mode to `add.tsx`:
- Accept route params (`entryId`, `entryType: 'task' | 'expense'`) or use router params.
- When editing: fetch entry via `repos.contributions.getById` or `repos.expenses.getById`, pre-fill all form fields, show `add.editBanner` title, use `add.update` button text.
- On submit: call `repos.contributions.update(id, data)` or `repos.expenses.update(id, data)` with `modifiedBy` set.
- Preserve all existing create functionality (mode switch, categories, members, photos, etc.).

**Verification:** Manual test — from Balances history, tap Edit on a task → navigates to Add screen in edit mode → form pre-filled → modify value → Save → returns to Balances → balances updated via delta, zero-sum holds.

### 3. Missing i18n keys for history actions (must-fix)

**Path:** `src/i18n/catalog.ts`

**Problem:** Catalog has generic add-screen edit/delete keys but no keys for history-specific actions (edit/delete/share from Balances activity list).

**Evidence:** Existing keys: `add.editBanner`, `add.update`, `add.errorEdit`, `add.errorDelete`, `add.deleteTitle`, `add.deleteConfirm`. Missing: history entry action labels and confirmations.

Ensure French accents and formulations are correct (e.g., `Modifier la tâche`, `Supprimer cette dépense`, `Partager`).
