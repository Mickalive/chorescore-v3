## 5. Does the candidate address the required fix?

**Yes, within Builder scope:**

- **(a) Cause identified — single concrete cause.** The repair targets exactly one root cause: a degraded adb server process that `adb reconnect` (transport reset) cannot recover. The repair replaces the transport reset with a full server process restart (`kill-server` + `start-server`) in all three places the reconnect is used (JS `adbReconnect()`, shell pre-E2E, shell post-install), plus a post-restart health check. There is no scope creep into boot timeout, install logic, or E2E assertions.
- **(b) Technically sound.** `adb kill-server` + `adb start-server` is a standard adb recovery technique. The emulator is a separate process from the adb server; killing the server does not affect the emulator. On restart, the new server discovers the running emulator via its console/adb ports on localhost (standard behavior). The restart points are all after boot completion (post-boot settle, post-install, and mid-E2E on timeout paths), so the emulator is fully booted.
- **(c) Bounded.** JS: kill 10s, start 10s, wait-for-device 30s, get-state 5s, plus fixed sleeps (3s+2s+1.5s) ≈ 6.5s nominal, ~60s worst case. Shell: matches the pristine pattern (`|| true` guards on every adb call; a failed restart degrades to the existing install-failure diagnostics rather than hanging).
- **(d) No masking.** Every positive assertion (`waitFor`, `tapLabel`, `findVisible`, `typeInto`, tab checks, demo-fixture checks) and every `assertAbsent` check (chrono, premium, warm-V2) is byte-identical to pristine. All E2E timeouts unchanged (Demarrer 300s, Appartement 60s, tabs 30s, etc.). The golden path still requires the actual UI nodes to appear, so a genuinely broken app cannot pass spuriously. The diagnostic echo mechanism and `exit "$E2E_EXIT"` are preserved.
- **(e) Cannot make the finalizer worse.** The kill-server restart is strictly more thorough than `adb reconnect` for a degraded server; for a healthy server it is a bounded no-op recovery. The only theoretical regression — an emulator that fails to re-register with the new server — is mitigated by the standard rediscovery mechanism, the `|| true` guards, and the runner-level step kill; and the JS path bounds wait-for-device at 30s.
- **(f) Not an empty delta.** `changedFiles=2`, `hasDelta=true`, `verificationOnly=false`, `agentExitCode=0` — the candidate is a concrete repair, not a verification-only cycle.
