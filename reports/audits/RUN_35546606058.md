## 1. Root cause of the trusted finalizer failure (run 35544223219)

The finalizer workflow (`chorescore-v3-finalize.yml`) triggers on the schedule `7,17,27,37,47,57 * * * *`. Run 35544223219 started at the **23:57 UTC slot on Sunday Sept 20, 2026**. The `Trusted product, privacy and cost gates` step runs `npm ci` then `npm run check` (typecheck + jest). With `npm ci` taking ~2–3 minutes, the jest suite executed **just after midnight UTC on Monday Sept 21, 2026**.

Two V3-04 test files asserted **exact week-period balances over fixed test data dated 2026-09-16** while calling `computePeriodContributionBalances` / `computePeriodFinancialBalances` with the default `referenceDate = new Date()`:

- `__tests__/domain/cost-gates-v3-04.test.ts` — `settlement outside period does not affect period balance` (expects `a = -2.5`);
- `__tests__/domain/materialized-balances.test.ts` — `settlement outside the period does not affect the period view while remaining in all-time` (expects `a = 30, b = -10, c = -20`) and `financial balances: settlement outside the period does not affect the period view` (expects `a = 1833, b = -1833`).

On Monday Sept 21 the week boundary computed from `new Date()` moved to `2026-09-21T00:00:00Z`, which **excludes** the Sept 16 entries. The week view became empty, so the exact assertions failed (actual balance `0` vs expected `-2.5`), failing the trusted gates step. The `reopen-on-failure` job then committed at `2026-09-21T00:00:57Z` (commit `bb0ad36`), which matches this early-gates failure — not the later emulator/E2E step (which would have taken 30+ more minutes).

This is a classic time-of-day flaky test: the tests were deterministic only when run on a date whose week boundary fell on or before Sept 16 (i.e., Sunday Sept 20 or earlier in that week).
