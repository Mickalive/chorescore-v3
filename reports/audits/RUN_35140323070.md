### 1. `src/features/app/AppContext.tsx` — demo fixture regression: root Groups list empty after demo sign-in

- **Problem**: `ensureDemoFixture` now creates the demo household via `repos.households.create()` (line 146), which assigns a **generated** id, while every subsequent fixture record (memberships lines 157–190, members lines 192–229, tasks/entries/todos lines 231–283) and `signIn` (line 299) still reference the constant `DEMO_HOUSEHOLD_ID` (`'h-core'`). `loadHouseholds` (lines 309–322) resolves each membership's `householdId` via `households.getById(m.householdId)` → `null` for `'h-core'`, so the root Groups screen shows **"Aucun groupe"** after demo sign-in and the demo group is unreachable. The previous baseline seeded the household with id `'h-core'` and the fixture was consistent; the repair comment "For in-memory, set the known ID by updating the created record" has no corresponding code. In the SQLite path the demo user is also created via `create()` (generated id), so `'demo-user-alex'` never exists and a duplicate user row is inserted on every sign-in. Additionally `reposReady` (line 73) is set but never consumed: a sign-in before repository init completes skips the fixture and `loadHouseholds` with no retry, and `repos` falls back to `{} as AllRepositories` (lines 355–368).
- **Evidence**: scratch jest test in a temp copy mirroring the exact `ensureDemoFixture` + `loadHouseholds` logic with in-memory repositories — `expect(loaded.length).toBe(1)` FAILED with `Received: 0`. `git diff --cached` shows `seed([{ id: DEMO_HOUSEHOLD_ID, ... }])` replaced by `await repos.households.create({...})` with no id assignment.
- **Required fix**: keep the demo fixture internally consistent — seed/create the demo household (and demo user) under the canonical ids, or use the id returned by `create()` consistently for memberships, members, tasks, entries, todos and `currentHouseholdId`; consume `reposReady` (or retry the fixture once repos are initialized) so an early sign-in cannot permanently skip the fixture.
- **Verification**: after demo sign-in the root list shows the "Appartement" group; tapping it opens the tabs rendering that group's data; a second sign-in does not duplicate the demo user.
