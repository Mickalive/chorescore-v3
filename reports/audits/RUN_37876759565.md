## Active Criterion
**V4-06 — À faire — Tâche ou Dépense**  
*À faire crée des items typés Tâche ou Dépense et leur complétion produit exactement une écriture ledger correspondante avec les champs nécessaires, offline-safe et atomique.*

---

## Scope Verified
- **Domain entities** (`src/domain/entities/index.ts`): `TodoKind = 'task' | 'expense'`, `TodoItem` carries `kind`, `expenseAmountMinor`, `expenseCurrency` — already present from V4-01 baseline.
- **Completion service** (`src/domain/services/todoCompletionService.ts`): `planTodoCompletion` overloaded for `CompletionInput` (task) and `ExpenseCompletionInput` (expense); validates kind/input match, amount/currency, split coverage, note/photo; snapshots category ratio; returns exactly one ledger entry per kind.
- **Atomic use-case** (`src/application/use-cases/completeTodoAtomic.ts`): `completeTodoAtomic` runs `planTodoCompletion` then persists `todo.update + contributions.create` OR `todo.update + expenses.create` inside a single `repos.withTransaction`; failure rolls back both; retry cannot duplicate.
- **UI screen** (`app/(tabs)/todos.tsx`): Create form with `Tâche | Dépense` kind selector; expense create collects planned amount + currency; completion mini-form confirms payer/amount/currency/participants (expense) or performer/value/beneficiaries (task); equal/custom split for both; optional note + photo; synchronous double-submit guard; routes through `completeTodoAtomic`; emits data-change signals for cross-tab refresh.
- **i18n catalog** (`src/i18n/catalog.ts`): FR/EN keys for `todos.kindTask` (`Tâche`/`Task`), `todos.kindExpense` (`Dépense`/`Expense`), `todos.plannedAmount`, `todos.completeTaskTitle`, `todos.completeExpenseTitle` — French accents exact, no forbidden wording.
- **Tests** (`__tests__/domain/v4-06-todo-task-expense.test.ts`): 14 tests covering screen wiring (source-level), i18n parity, typed creation, completion produces exactly one matching entry (task → ContributionEntry, expense → ExpenseEntry with confirmed amount/currency, custom splits snapshotted, note/photo carried), offline atomicity (failure injection: todo-update failure rolls back, expense-create failure rolls back, retry yields exactly one entry).
