## Findings

### Finding 1 — MUST-FIX: equal-timestamp pagination gap (skipped entries)
- **Path:** `src/infrastructure/repositories/InMemoryRepositories.ts` + `SqliteRepositories.ts` (`getByHouseholdPaginated`) + `app/(tabs)/add.tsx` (merged path)
- **Problem:** cursor is `occurredAt < cursor` (exclusive) with `ORDER BY occurredAt DESC` and no secondary sort key. When >PAGE_SIZE entries share one timestamp, the first page returns PAGE_SIZE of them, the cursor becomes that timestamp, and the next page excludes ALL entries with that timestamp — the overflow entries are permanently unreachable. Violates "no skipped entries / no gaps".
- **Evidence:** simulation with 20 equal-timestamp contributions + 5 older (PAGE_SIZE=15): page1=15 (cursor=T), page2=5 older, page3=0; 5 entries unreachable. SQLite uses the same exclusive cursor without a tie-break key. The candidate's tie-break test covers only the pure merge with 2 entries.
- **Required fix:** composite cursor (occurredAt + id) with deterministic secondary ordering in both repos; add a test with ≥PAGE_SIZE+1 equal-timestamp entries asserting all are reachable exactly once.
- **Verification:** page through until `hasMore=false` on the equal-timestamp fixture; assert every seeded id reachable; `npm run check` green.

### Finding 2 — MUST-FIX: 'Charger plus' race produces duplicate ids
- **Path:** `app/(tabs)/add.tsx` (`loadHistory` + `activityEntries`)
- **Problem:** no in-flight guard; two concurrent `loadHistory(true)` calls with the same cursor append the same page twice; `paginateActivityLog` does not dedupe → duplicate rows/ids.
- **Evidence:** simulation of two concurrent load-more calls on 40+40 entries: merged=90, unique=60, 30 duplicates.
- **Required fix:** in-flight guard (ref) or dedupe by id in the merge; add a concurrent load-more test.
- **Verification:** fire two concurrent load-more calls; assert no duplicate ids; `npm run check` green.

### Finding 3 — MUST-FIX: share message uses current household unit instead of entry unit
- **Path:** `app/(tabs)/add.tsx` (`handleShare`, history row display)
- **Problem:** contribution values are labeled with the current `householdUnit` rather than the entry's stored `unit`; after a Minutes↔Points switch, historical entries are silently mislabeled (e.g., "15 pts" for a 15-minute entry). Violates §18.
- **Evidence:** `message = \`${e.label} - ${e.value} ${householdUnit === 'minutes' ? 'min' : 'pts'} ...\``; `ContributionEntry.unit` exists and is ignored; history row uses `unitLabel` the same way.
- **Required fix:** use `e.unit` in the share message and history row display.
- **Verification:** entry with unit 'minutes' shared while household unit is 'points' → message shows "min"; `npm run check` green.

### Finding 4 — MUST-FIX: custom-split validation does not block submit
- **Path:** `app/(tabs)/add.tsx` (expense form + `submitExpense`)
- **Problem:** the inline sum error is displayed but the submit button stays enabled; repositories persist expenses without write-time validation (`allocateExpense` only runs at balance-computation time), so an invalid custom-split expense can be written and later make financial balance computation throw.
- **Evidence:** Button disabled condition is only `!title || !amountRaw || isSubmitting`; `SqliteRepositories.create`/`InMemoryExpenseEntryRepository.create` insert directly; `expenseLedger.allocateExpense` throws on sum mismatch only when balances are computed.
- **Required fix:** block submit when `sum(customShares) != amountMinor` (disable button or early-return with the inline error).
- **Verification:** invalid custom shares → inline error and no write; `npm run check` green.

### Finding 5 — Minor: share adapter instantiated directly
- **Path:** `app/(tabs)/add.tsx` (`handleShare`)
- **Problem:** `new LocalSystemShareAdapter()` bypasses `services.share` from the app context (port honored, DI bypassed).
- **Required fix:** use `services.share` from `useApp()`.

### Finding 6 — Minor: Android Alert 4-button limit drops "Hier"
- **Path:** `app/(tabs)/add.tsx` (date/heure selectors)
- **Problem:** 4 Alert buttons; RN Alert on Android supports at most 3, so "Hier" is dropped on Android.
- **Required fix:** platform-conditional button list (≤3 on Android).

### Finding 7 — Minor: transient merged-order skew with independent cursors
- **Path:** `app/(tabs)/add.tsx` (merged pagination)
- **Problem:** with skewed timestamps the merged view is not a prefix of the true merged stream until all pages are loaded (newer contributions hidden while older expenses shown). All entries remain reachable; inherent to the per-type-page approach the task permits.
- **Required fix:** optional; document or switch to merged-cursor keyed pages.

### Finding 8 — Minor: merge limit 10 000 is technically still a cap
- **Path:** `app/(tabs)/add.tsx` (`activityEntries`)
- **Problem:** satisfies "not hard-capped at 150" but beyond 10 000 loaded entries older pages would be hidden again.
- **Required fix:** optional; remove the limit or virtualize the list.

### Finding 9 — Minor: loadHistory fetches both repos regardless of filter
- **Path:** `app/(tabs)/add.tsx` (`loadHistory`)
- **Problem:** filter=contribution still fetches expenses (bounded per page, wasteful).
- **Required fix:** optional; skip the stream excluded by the active filter.
